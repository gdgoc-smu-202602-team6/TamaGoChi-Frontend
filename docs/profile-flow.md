# 마이 프로필·통계·목표 예약

## 구현 범위와 디자인

사용자의 마이 시안과 기획 v4 `23-mypage`를 참고했다. 하늘색 배경·네이비 테두리·단단한 그림자, 게임 헤더와 MY PAGE 제목, 캐릭터 프로필과 Level·XP, 노랑/분홍/초록 요약 카드, 주간 막대 차트와 설정 목록을 반영했다. 서버 계약에 없는 동아리 파트 배지나 시안의 예시 통계는 추가하지 않았다.

`src/app/(tabs)/mypage.tsx`는 `features/profile/profile-screen.tsx`를 내보낸다. 프로필 카드, 주간 차트, 목표 편집기와 조회·저장 훅은 기능 폴더에 나눴다. 공통 헤더·카드·입력·버튼·진행 막대를 재사용한다. 패키지와 내비게이션 구조는 변경하지 않았다. 캐릭터는 Home과 같은 교체 가능한 임시 SVG이며 실제 장착 에셋 렌더링은 남아 있다.

연결한 범위는 프로필 조회, 공부 통계, 하루 목표 예약, 기존 내 계정 진입이다. 잠금한 앱 관리·보유 아이템 전용 목록·내 방명록은 준비 중으로 비활성화했다. 닉네임 편집·동아리별 설정 등은 이번 화면 작업에 추가하지 않았다.

## API와 표시

Backend `98441b9`의 OpenAPI 0.1.0과 Stats·DailyGoals 컨트롤러, 목표 이력·LevelCurve 도메인을 확인했다. 계정별 고정 토큰을 쓰는 Profile 서비스를 기존 Provider에 추가했다. API 모드 실패를 Mock으로 대체하지 않는다.

| 경로 | 사용 |
| --- | --- |
| `GET /users/me` | 닉네임 |
| `GET /users/me/stats` | Bolt·Level·누적 XP·레벨 XP 기준·오늘/주간 시간·연속 출석·이용 일차·월~일 기록 |
| `GET /users/me/dailyGoals` | 목표 버전 이력. 오늘 적용되는 목표와 미래 예약을 구분 |
| `POST /users/me/dailyGoals` | `{ startOn, minutes }`로 다음 서비스 날짜부터의 목표 생성 |

XP 막대는 `(xp - levelXp) / (nextLevelXp - levelXp)`를 0~100%로 제한해 표시한다. 레벨이 보존되어 XP가 현재 레벨 하한보다 낮아도 음수 막대를 만들지 않는다. 다음 레벨까지 남은 XP도 서버 값으로 표시한다. Web·모바일의 로컬 XP 정산으로 서버 통계를 바꾸지 않는다.

주간 차트는 서버가 준 월~일 순서와 초 단위 시간을 사용한다. 각 열에 그날의 `goalMinutes` 점선을 표시하므로 목표가 바뀐 주를 단일 목표선으로 표현하지 않는다. 0초인 날은 채운 막대를 만들지 않는다. 각 열의 접근성 이름에 날짜·요일·공부시간·목표·달성 상태를 제공한다. 진행 중 공부 시간도 서버 조회값에 포함된다. 마이 진입·foreground 복귀·화면에 있는 동안 60초 간격·당겨 새로고침으로 갱신한다.

## 목표 예약과 오류 복구

- 기본 180분이며 30~720분 범위의 정수, 10분 단위만 허용한다. 입력과 ±10분 버튼을 제공한다.
- 적용 날짜를 명시하고 한국시간 오전 4시부터 적용한다고 안내한다. 오늘 목표와 주간 과거 목표는 바꾸지 않는다.
- API는 같은 `startOn`을 한 번만 생성하고 수정/삭제 경로가 없다. 내일 예약이 있으면 해당 내용을 보여주고 변경을 막는다. 다른 미래 날짜의 예약도 숨기지 않는다.
- 중복 탭을 막고 POST 후 이력을 다시 읽는다. 응답 유실 뒤에도 같은 날짜·분량의 예약을 확인하면 완료로 표시한다. 다른 목표가 먼저 예약돼 409가 오면 실제 예약과 충돌 안내를 보여준다.
- 재조회까지 실패하면 이전 데이터를 보존하고 저장을 막는다. 다시 불러오기는 GET만 수행한다. 목표 POST를 자동 재전송하거나 오프라인 예약 성공으로 처리하지 않는다.
- 날짜가 바뀐 편집은 로컬 검사 또는 서버 검증 후 다시 조회한다. 적용일이 바뀌면 편집기를 다시 만든다. 입력한 값이 새 날짜로 자동 저장되지 않는다.
- 서비스 날짜는 조회 응답의 HTTP Date가 읽히면 이를 기준으로 삼고, 노출되지 않으면 기기의 KST 04:00 날짜를 사용한다. 실제 적용일 허용 여부는 서버가 최종 검증한다. Web에서 Date 헤더 노출과 기기 시계가 어긋난 실기기 검증은 남아 있다.
- 계정 변경 시 기존 게임 scope가 폐기되므로 늦은 응답과 이전 계정의 화면·편집 상태를 재사용하지 않는다.

## Mock

기존 `@tamagochi/mock-study/v1` 레코드에 선택적인 `goals` 배열을 추가한다. 기존 공부·상점 기록은 삭제하거나 초기화하지 않는다. 예약은 동일한 직렬 큐와 저장 작업으로 보관하며, 종료 세션이 오전 4시를 넘으면 각 날짜의 목표로 최초 보너스를 계산한다.

Mock XP는 확인한 서버 곡선 `25 × (L−1) × (L+2)`의 초기 레벨 하한에 저장된 종료 결과 XP를 더한다. Home·Profile·상점의 레벨과 해금이 일치한다. 진행 중 XP를 미리 지급하지 않지만, 오늘/주간 시간에는 활성 세션을 포함한다. 출석 연속 일수는 기록에 있는 연속 날짜, 이용 일차는 최초로 남아 있는 날짜를 기준으로 한다. 실제 계정 생성일·미출석 상태 정산을 복제하는 것은 아니다.

## 검증

```powershell
npm.cmd run typecheck
npm.cmd run lint -- --no-cache
npm.cmd test
```

총 72개 테스트에 이번 작업의 13개를 추가했다. 서버 통계·누적 XP 기준, 목표 이력, 입력 범위, KST 04:00·월/연도 경계, HTTP Date에 따른 시계 보정, 중복 날짜·영수증 검증, 잘못된 응답, Mock 날짜별 목표 보너스·레벨·공유 기록·저장 실패·손상 보존을 확인했다.

격리된 Chrome에서 API 응답을 주입해 인증 진입 제한, XP 28% 표시, 입력·증감 버튼, 한 번의 POST, 내일 예약·새로고침, 응답 유실·재조회 실패, 409 충돌, 편집 중 날짜 변경, 0 통계, 계정 변경·인증 만료와 320·390·1280px 배치를 확인했다. Mock에서는 예약 → 재실행 → 공부 종료 레벨업 → Home·마이·상점의 레벨 일치 → 구매 → 마이 잔액 갱신과 기록 보존을 확인했다. 운영 계정·공부·목표는 생성하거나 수정하지 않았다.

Android·iOS·Web 번들 내보내기까지 확인한다. 실제 인증 계정과 실기기에서 목표 저장·날짜 전환·배경 복귀·화면 읽기 기능 검증은 남아 있다. Metro 개발 SSR의 기존 `unknown module` 문제는 별도이며, Web 미리보기는 내보낸 빌드를 사용한다.

## 미리보기

```powershell
$env:EXPO_PUBLIC_DATA_MODE='mock'
npx.cmd expo export --platform web --output-dir .expo/preview
npx.cmd expo serve .expo/preview --port 8082
```

같은 PC에서 `http://localhost:8082/mypage`로 접속한다. 이미 실행 중이라면 서버를 종료하고 다시 내보낸 뒤 시작해야 새 코드가 보인다. 실제 API 확인은 `EXPO_PUBLIC_DATA_MODE=api`로 새로 내보내고 로그인해서 진행한다.
