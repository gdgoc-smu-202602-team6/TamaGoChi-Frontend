# 다마GoC치 UI 디자인 기준

## 기준과 우선순위

기능 명세를 가장 우선하고, 충돌하지 않는 범위에서 사용자가 제공한 Claude Design 시안 이미지를 실제 UI 구현의 주요 참고자료로 사용한다. 별도 Figma 작업은 예정되어 있지 않다.

참고자료는 대화에 첨부된 내 방, 공지, 상점, 마이 화면과 방 확대 이미지 총 5개다. 원본 이미지는 대화 첨부자료이며, 저장소에 최종 에셋으로 추가된 것은 아니다.

- 시안의 레이아웃, 정보 배치, 컴포넌트의 상대적인 크기와 위치를 최대한 반영한다.
- 시안에 그려진 숫자와 문구가 기능 규칙이나 API 계약을 결정하지 않는다.
- 명세나 시안에 없는 기능과 동작을 임의로 추가하지 않는다.
- 확정하기 어려운 요소는 기존 구조와 기능 명세에 맞는 최소 구현을 우선한다.
- 화면을 구현하기 전에 참고할 시안 요소와 명세에 맞게 조정할 부분을 사용자에게 간단히 정리한다.

## 공통 시각 요소

| 요소 | 구현 기준 |
| --- | --- |
| 분위기 | 다마고치·8-bit·Pixel Art 기반의 귀엽고 깔끔한 모바일 게임 |
| 배경 | 밝은 하늘색~블루 계열의 넓은 배경, 픽셀 구름과 하단 풀·흙 장식 |
| 외곽선·텍스트 | 진한 네이비, 굵은 테두리와 아래로 드리운 단단한 그림자 |
| 강조 | 노란색 계열의 주요 버튼, 선택 상태, Bolt와 보상 요소 |
| 보조색 | 시안의 녹색·분홍색·보라색 등을 상태와 정보 구분에 제한적으로 사용 |
| 카드·버튼 | 둥근 모서리와 네이비 외곽선, 두께감 있는 게임 버튼·배지 형태 |
| 헤더 | 좌측 게임 로고/화면 제목, 우측 코인 아이콘과 숫자가 있는 Bolt 배지 |
| 하단 탭 | 내 방·공지·상점·마이 순서, 네이비 바 위 노란색 선택 영역과 아이콘·라벨 |

흰색·크림색 카드는 시안처럼 사용할 수 있다. 배경과 게임 장식, 방·캐릭터, 테두리와 보상 표현을 함께 유지하여 일반적인 생산성 대시보드로 바꾸지 않는다.

시안 이미지의 픽셀 크기를 그대로 화면 좌표로 사용하지 않는다. 모바일의 가용 영역과 safe area 안에서 상대적 크기·간격·배치를 유지하고, 작은 화면과 Web에서도 내용이 잘리거나 겹치지 않게 한다. 기기 프레임, 시각·LTE·배터리 표시, 홈 인디케이터는 앱 내부에 가짜 UI로 그리지 않는다.

## Typography

- 제목, 타이머·재화·레벨 등의 숫자, 짧은 강조 요소에는 Galmuri 같은 픽셀 폰트를 사용할 수 있다.
- 긴 한글 본문과 일반 UI 텍스트에는 가독성 좋은 폰트를 사용한다.
- 픽셀 폰트를 모든 텍스트에 일괄 적용하지 않는다. 실제 폰트 파일이 정해지기 전에는 기존 시스템 폰트를 사용한다.
- 제목·본문·보조 문구·숫자의 역할과 크기, 줄 높이는 공통 typography 값으로 관리한다.

## 시안과 기능 명세가 다른 부분

| 시안 표현 | 실제 구현 기준 |
| --- | --- |
| 25:00 카운트다운과 15·25·50·90분 선택 | 미리 시간을 정하지 않는 경과시간 누적 방식. 일시정지 없이 사용자가 공부를 끝낼 때 종료한다. 시간 프리셋은 추가하지 않는다. |
| Heart 5칸 | 사용자 단위 Heart 최대 4개 |
| 버그 5마리 | 명세의 Bug 3마리 생성 규칙과 사용자 상태를 사용한다. Bug가 있는 동안 누적 공부 60분마다 1마리를 제거한다. |
| 고정된 +35 보상 | 종료된 세션의 인정시간과 보상 결과를 사용한다. 공부 1분당 1 Bolt·1 XP, 세션의 분 미만 시간은 버린다. 출석·목표 보너스는 명세와 서버 결과를 따른다. |
| 화면의 Bolt·레벨·읽지 않은 수·아이템 가격 등 예시 숫자 | 분리된 Mock 또는 Service의 값을 표시한다. 화면과 공통 컴포넌트에 고정하지 않는다. |
| 공지의 AI·Dev·디자인·스터디 필터 | 동아리에서 관리하는 동적 카테고리·하위 카테고리 데이터로 렌더링한다. 시안의 항목을 고정하지 않는다. |
| 상점의 가구·벽지·캐릭터 세 카테고리 | 명세에 있는 Furniture·Wallpaper·Character·Room 네 카테고리를 지원한다. |
| 공지의 펼치기, 마이의 잠금한 앱 관리 | 화면 표현을 참고하되 실제 동작은 명세 범위에서 구현한다. 앱 차단은 Device Local 기능이며 별도 플랫폼 검토 시 구현한다. |

오늘 공부시간, 출석, Heart, Bug, 목표, 일일 보상, 통계의 하루 경계는 KST 오전 4시다. 가능하면 서버가 계산한 값을 사용한다. 시안의 달력·차트 표현으로 이 규칙을 바꾸지 않는다.

승인되지 않은 동아리의 공지·회원 방 접근 제한, 사용자 단위 보상·상태, 상점의 서버 카탈로그 기준 등 기존 기능 명세도 그대로 적용한다. 마이의 목표시간은 기본 3시간, 30분~12시간 범위에서 10분 단위로 설정하며 다음 서비스 날짜부터 적용한다.

## 에셋과 공통 구현

- 최종 캐릭터·방·가구·아이콘 에셋이 없으면 교체 가능한 placeholder/component로 구현한다. 화면 전체를 하나의 시안 이미지로 붙이지 않는다.
- 방 렌더링, 캐릭터, 가구와 상태 장식을 분리하여 최종 디자인 에셋을 교체하기 쉽게 한다. 시안의 방 이미지를 임의로 최종 에셋으로 확정하지 않는다.
- 색상, typography, spacing, border, radius, 그림자는 기존 `src/constants/theme.ts`를 기반으로 공통화한다. 추후 분리가 필요하면 실제 사용 범위에 맞게 나눈다.
- 버튼, 카드, 상태 배지, Bolt 표시 등 반복되는 UI는 기존 `src/components/` 안의 재사용 가능한 컴포넌트로 만든다. 기능 전용 구현은 해당 기능 폴더에 둔다.
- Mock·Service·Type은 화면과 분리한다. API endpoint, 응답 필드, XP 레벨 구간, 아이템 가격과 해금 조건을 시안만 보고 확정하지 않는다.
- 현재 모바일 `NativeTabs`와 웹 탭 구현을 출발점으로 삼는다. 시안의 플로팅 탭 모양을 맞추기 위해 공통 Navigation 변경이 필요하면 변경 이유와 범위를 먼저 설명한다.
- 기존 테마 동작을 고려한다. 시안에 없는 다크모드 전체 디자인을 임의로 확장하지 않는다.

## 화면 작업 순서

1. 현재 저장소와 해당 화면의 기능 명세를 확인한다.
2. 이번에 반영할 시안의 레이아웃·색상·컴포넌트와 명세상 조정할 부분을 짧게 알린다.
3. 공통 토큰·컴포넌트와 교체 가능한 에셋 표현을 필요한 만큼 추가한다.
4. 기능 단위로 구현하고 타입·린트와 해당 화면의 실행을 확인한다.
5. 변경 파일과 검증 결과, 아직 대체 에셋을 쓰는 부분을 알린다.
