# 친구 방·좋아요

## 화면과 디자인

2026-11-04(KST)에 Backend `98441b9`의 Members·Room·Stats·Likes 컨트롤러와 PlayerViews·LikeRepository, OpenAPI 0.1.0을 확인했다. 기획 v4의 `friends`·`friendRoom` 구성을 참고해 하늘색 배경, 노란 FRIENDS 제목, 네이비 테두리의 두 열 방 카드, 방 위의 버그/좋아요 배지를 사용한다. 방문 화면은 큰 방 아래에 레벨·오늘 공부시간·좋아요를 둔다. 긴 텍스트는 기존 시스템 폰트로 표시하고 새 에셋·패키지는 추가하지 않았다.

내 방의 `친구 방`에서 `/friends`를 연다. 가입한 동아리 선택은 공지와 같은 `ClubProvider`를 사용한다. 선택된 동아리에서 본인을 제외한 부원을 오늘 공부시간 내림차순으로 표시하며 같은 시간이면 서버 목록 순서를 유지한다. 카드에는 방 썸네일·닉네임·동적 파트·레벨·오늘 공부시간·버그·좋아요 수를 표시한다. 다른 부원이 없으면 빈 목록, 가입한 동아리가 없으면 가입 진입을 제공한다.

카드는 `/clubs/{clubId}/friends/{memberId}`로 이동한다. 사용자 ID와 부원 ID를 구분해 현재 부원 자격에서 방문할 사용자를 찾는다. 기존 `RoomScene`으로 장착·배치·방 크기·캐릭터·버그를 그리며 드래그나 장착/편집 진입은 제공하지 않는다. Heart는 최대 4개, Bug는 최대 3마리다. 후속 [방명록](guestbook-flow.md)을 방 아래에 연결했으며 방 헤더와 글을 하나의 FlatList로 스크롤한다.

## API

| 요청 | 용도 |
| --- | --- |
| `GET /clubs/{clubId}/members/me` | 로그인 계정의 현재 소속 확인 |
| `GET /clubs/{clubId}`, `/parts` | 동아리 이름과 파트 |
| `GET /clubs/{clubId}/members?pageSize=200` | 전체 부원 페이지 조회 |
| `GET /items` | 공통 방 에셋 카탈로그 |
| `GET /users/-/room:batchGet?userIds=...` | 썸네일·장착·버그·좋아요 |
| `GET /users/-/stats:batchGet?userIds=...` | 레벨·오늘 공부시간 |
| `GET /users/{userId}/room`, `/stats` | 방문하는 방의 최신 정보 |
| `PUT /users/{userId}/likes/me` | 좋아요, 본문 없음 |
| `DELETE /users/{userId}/likes/me` | 좋아요 취소, 본문 없음 |

일반 부원도 사용할 수 있다. 관리 권한이나 역할 목록은 조회하지 않는다. 다른 사용자의 보유 아이템·계정 상세도 요청하지 않으며 공통 카탈로그와 서버의 장착/배치를 검증해 방을 표시한다. 목록의 부원 페이지를 모두 받은 뒤 본인을 제외하고 최대 100명씩 나눈다. 묶음 안에서 방과 통계는 병렬 조회한다. 빈 목록에서는 카탈로그/배치 조회를 생략한다.

페이지 토큰·사용자 경로·배치 쿼리를 인코딩한다. 내 계정/동아리 ID·중복 부원/사용자·반복 토큰·알 수 없는 파트, 방/통계의 사용자 ID·배치의 누락/중복/다른 사용자·장착 부위/위치·조건·레벨/공부시간·좋아요 값을 검사한다. 배치 응답은 사용자 ID로 연결해 위치가 달라도 서로의 방을 섞지 않는다. 쉼표로 구분되는 배치 계약에 모호한 사용자 ID는 불완전한 목록으로 표시하지 않는다. 부분 실패를 임의의 Mock이나 기본 방으로 대체하지 않는다.

오늘 공부시간에는 서버가 계산한 진행 중 세션과 KST 오전 4시 경계를 사용한다. 화면 진입·복귀·foreground·수동 재확인 시 다시 읽으며 클라이언트에서 친구의 공부시간을 임의 누적하지 않는다.

## 좋아요·오류·격리

좋아요는 동아리별이 아닌 사용자 단위다. 다른 동아리에서도 같은 사용자를 방문하면 하나의 좋아요 상태를 사용한다. 변경 직전에 현재 소속과 대상 부원 원본을 다시 확인하고, 대상이 바뀌었으면 요청 없이 재확인을 요구한다. 이미 원하는 상태이면 쓰지 않는다. 요청 후 방을 다시 읽어 실제 상태와 수를 표시하며 낙관적으로 숫자를 더하지 않는다.

동시에 누른 변경은 화면과 서비스에서 순서대로 처리한다. 조회는 독립적으로 실행해 이전 화면의 느린 요청이 다른 동아리나 방의 조회를 막지 않는다. 확정된 4xx는 재전송하지 않는다. 네트워크·타임아웃·5xx·응답 유실은 GET으로 확인하며 PUT/DELETE를 자동 반복하지 않는다. 원하는 상태를 확인하지 못하면 기존 표시를 읽기 전용으로 유지하고 `방 다시 확인`을 안내한다. 이 버튼은 조회만 하며 이후 작업은 사용자가 새로 선택한다.

401·403·404·계정 변경에서는 이전 방 정보를 제거한다. 소속이 없거나 해당 동아리에서 부원이 사라지면 이전 직접 주소로도 볼 수 없다. 목록·방의 늦은 응답은 화면이 해제되면 적용하지 않고 동아리/대상 변경은 새 화면 인스턴스를 사용한다. API 모드의 방문 내용과 미확정 좋아요 요청은 로컬 저장소에 캐시하지 않는다. 서버가 마지막 접근 권한을 판정하며 여러 기기의 동시 좋아요 결과까지 잠그는 계약은 없다.

## Mock과 검증

Mock은 기존의 실제 부원·파트·생성·승인·강퇴·탈퇴 상태를 함께 읽는다. 사용자 ID에서 만드는 데모 방·통계는 동아리 사이에 같고 닉네임/파트는 해당 부원 자격을 따른다. 기존 방 렌더러와 교체 가능한 아이템 에셋을 사용한다. `@tamagochi/mock-likes/v1`의 `{ version: 1, userIds: [...] }`만 저장하며 저장소별 변경 큐로 동시 변경을 보존한다. 개인 공부·볼트·방·기존 동아리 기록은 수정하지 않는다. 저장 실패·손상 기록을 자동 초기화하지 않으며 읽기만 할 때 초기 파일을 쓰지 않는다.

타입·린트와 총 301개 테스트, API Android/iOS/Web·Mock Web 번들 생성이 통과했다. 새 19개 테스트는 전체 페이지·본인 제외·공부시간 정렬·100명 묶음·ID별 연결·일반 부원 접근·빈 목록·DTO/위치 검증·안전한 경로·정확한 본문 없는 요청·중복/원본 변경·응답 유실/미적용/접근 회수·느린 조회 독립, Mock 사용자별 좋아요 유지·동아리별 접근·강퇴/탈퇴·손상·동시 저장·개인 데이터 보존을 검증한다.

격리 Chrome의 가짜 API로 인증 제한·내 방 진입·일반 부원의 전체 목록·정렬·배치 ID 연결, 중복 클릭 한 번 처리·동아리 사이 좋아요 공유·적용 후 응답 유실·조회 실패/미적용 후 조회만 하는 복구를 확인했다. 이전 방/목록 조회를 지연시킨 채 다른 방/동아리로 이동해 이전 응답이 새 화면에 적용되지 않음을 확인했다. 잘못된 배치 응답 때 변경 차단·권한 회수 후 정보 제거·빈 부원/소속·계정 전환·만료도 확인했다.

Mock에서는 두 동아리의 사용자별 좋아요 공유·재진입 유지·중복 저장 방지·저장 실패/손상 보존·명시적 재확인, 실제 강퇴/탈퇴 후 직접 방문 차단과 다른 동아리 접근 유지, 공부 결과 보존·생성한 새 동아리의 빈 목록을 확인했다. API/Mock 모두 320×568·390×844·1280×844에서 가로 넘침과 방/카드 배치를 확인했다. 운영 API 네트워크를 차단했으며 운영 좋아요나 사용자 데이터를 변경하지 않았다. 실제 계정·Android/iOS 실기기·화면 읽기·긴 목록 성능·다중 기기 동시 반영 검증은 남아 있다. 최종 방 에셋도 임시 상태다.

## 미리보기

같은 PC에서 `http://localhost:8082/friends`를 열거나 내 방의 `친구 방`을 누른다. Mock 기본 두 동아리에서 같은 부원을 방문하면 좋아요가 공유된다. 현재 브라우저에 남은 강퇴·탈퇴·생성 상태에 따라 목록이 달라질 수 있다. 실제 API 모드는 로그인과 승인된 동아리 자격이 필요하다.
