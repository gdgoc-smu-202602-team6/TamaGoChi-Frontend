# UI·설정 구조 정리 (2026-11-04)

사용자의 최신 피드백에 따라 게임의 방·캐릭터 구성은 유지하고 앱의 정보·탐색 UI를 정리했다. 이전 시안의 큰 로고와 강한 색·테두리를 그대로 복제하지 않는다. 기능 명세·권한·오류/재시도·공부 및 배치 저장 계약은 유지한다.

## 화면

- 앱명은 시작 시 약 1.5초 표시한다. 네이티브 시작 화면은 배경만 표시하고 앱 오버레이에서 이름을 보여준다. 네이티브 설정 변경은 다음 바이너리 빌드부터 적용된다.
- 내부 화면은 작은 제목과 아이콘을 사용한다. 공통 카드·버튼은 얇은 경계, 블루 그레이·라벤더·민트·아이보리 팔레트를 사용한다.
- 내 Bolt·Level/XP는 마이 프로필에서 확인한다. 홈·공지·상점의 반복 게임 헤더는 제거했다. 상점 가격·해금 레벨과 친구의 레벨 표시는 기능 정보이므로 유지한다.
- 공부 시작은 원형 재생 아이콘이다. 공부 중·결과 화면의 홍보성 부제와 반복 보상 설명도 줄였다. 실행/복구/처리 중 접근성 이름과 중복 실행 방지는 기존 상태를 따른다. 보상 공식·홍보 문구를 제거했으며 출석·버그 진행 정보는 남긴다.
- 친구 목록/방 방문의 상단 복귀는 44×44 아이콘이다. 새로고침도 아이콘으로 표시한다.
- 방 편집은 선택 안내창·선택 테두리를 제거했다. 물건의 직접 드래그, 접근성 선택 정보, 취소 복원·최종 이동 좌표 반영·저장 전 이탈 확인은 유지한다.

## 탐색

| 출발 | 위치 | 기능 |
| --- | --- | --- |
| 마이 톱니바퀴 | `/settings` | 내 계정 / 공부 / 내 방 / 동아리별 행 묶음 |
| 설정 → 하루 목표 시간 | `/settings/study-goal` | 기존 목표 편집기·예약·충돌/재조회 처리 재사용 |
| 설정 → 동아리 또는 공지 톱니바퀴 | `/clubs/{clubId}/manage` | 공지 / 동아리 운영 / 내 활동 묶음 |
| 공지 + 또는 동아리 설정 → 공지 쓰기 | 기존 compose 경로 | `notices.write` 확인 후 진입 |

동아리 관리 행은 현재 권한을 조회한 뒤에만 노출한다. 포커스·foreground 복귀와 관리 행 클릭 직전에 재확인하고, 권한이 없거나 조회에 실패하면 관리 기능을 열지 않는다. 가입 신청·부원/역할·파트·기본 설정·공지 분류는 각각 독립된 권한을 사용한다. 일반 부원에게도 본인의 소속/알림·탈퇴는 제공한다. 새 경로도 `RequireAuth`로 감싼다. 기존 상세 관리 화면의 서버 가드도 유지한다.

닉네임·소속 설정은 기존 임시 변경 이탈 확인을 유지한다. 새 설정 허브가 서비스를 복제하거나 임의의 설정 토글을 추가하지 않는다.

## 에셋

`theme.ts`는 앱 UI 토큰, `asset-palette.ts`는 가구·소품의 코드 기반 임시 에셋 팔레트를 관리한다. 후속 사용자 지시에 따라 기본 캐릭터와 방 자체는 UI 정리 전의 색으로 복원했다. 기본 캐릭터의 갈색·크림색, 방 벽과 나무 경계의 기존 색상을 유지하며 공유 렌더러를 사용하는 홈·공부·프로필·친구 방·방 편집에 함께 반영된다. 헤더·버튼·설정 구조와 카탈로그 가구·소품의 파스텔 표현은 유지한다. 디자이너가 전달한 GIF/PNG 원본을 변형하거나 임의로 최종 에셋으로 확정하지 않았다. 실제 에셋 교체는 후속 전달 자료와 표시 크기를 확인한 뒤 진행한다.

## 검증

- 타입 검사·린트(경고 없음)·기존 회귀 테스트 388개를 통과했다. 스타일/문구와 동일한 내용을 검사하는 단위 테스트는 추가하지 않았다.
- 최종 소스의 API Android/iOS Hermes·Web SSR, Mock Web SSR 내보내기를 통과했다. 새 의존성은 추가하지 않았다.
- 로컬 Mock에서 시작 화면 이후 로고 비노출, 홈 재생 아이콘 → 공부 → 종료 결과 → 홈, 마이의 Bolt/Level, 목표 시간 190분 예약, 닉네임 미저장 변경 확인창과 복귀를 확인했다.
- 운영진의 공지/운영 관리 그룹과 공지 분류 화면 진입, 일반 부원의 관리 행·쓰기 아이콘 숨김을 확인했다. 클릭 직전 권한 재조회·오래된 응답 무효화는 코드로 점검했다.
- 친구 목록 → 친구 방 → 목록 → 내 방의 아이콘 복귀와, 선택 안내창 없이 시계 직접 드래그 → 완료 → 홈 배치 반영을 확인했다. 드래그 좌표/취소 계산은 기존 회귀 테스트로 함께 확인했다.
- 320×568·390×844·1280×844 배치와 가로 넘침을 확인했다. 아이콘 버튼은 접근성 이름을 제공하며 설정 행은 긴 제목을 줄바꿈한다.
- API 모드의 `/settings`, `/clubs/{clubId}/manage`에 비로그인 직접 접속하면 로그인으로 이동했다. 운영 데이터 쓰기는 하지 않았다.
- 최종 Mock SSR 서버와 브라우저 번들의 모드를 맞춘 뒤 새 탭에서 시작 화면 → 홈을 다시 확인했으며 브라우저 오류는 없었다.

미리보기: `http://localhost:8082`. 로컬 Mock 화면이며 운영 계정 로그인·Android/iOS 설치·실기기 검증을 뜻하지 않는다. 최종 디자인 에셋 교체와 네이티브 시작 화면의 바이너리 반영은 후속 확인 범위다.

캐릭터·방 색감 복원 후에는 두 에셋 소스가 UI 변경 전 커밋 `246a32f`와 동일함을 확인했고, 타입·린트·Mock Web SSR 빌드와 모바일 크기의 홈 표시를 다시 확인했다. 새 미리보기 탭의 브라우저 오류는 없었다. 좌표·드래그·서비스 로직은 변경하지 않았다.

SSR 미리보기를 다시 띄울 때는 export와 serve 양쪽에 `EXPO_PUBLIC_DATA_MODE=mock`을 지정한다. 브라우저 번들과 서버의 모드가 달라지면 인증 초기 화면과 첫 렌더가 일치하지 않을 수 있다.
