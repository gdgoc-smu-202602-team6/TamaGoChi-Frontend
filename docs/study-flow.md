# Study 화면과 Mock 서비스

이 문서는 명시적인 `EXPO_PUBLIC_DATA_MODE=mock`의 로컬 구현을 설명한다. 현재 기본 모드의 [Home·Study 서버 연동](study-api-flow.md)과 구분한다. API 모드에서는 이 Mock으로 오류를 대체하거나 로컬 정산하지 않는다.

## 화면과 상태

- 내 방의 공부 시작 버튼은 세션 저장이 성공한 뒤 `/study`로 이동한다.
- 진행 중인 세션이 있으면 새 세션을 만들지 않고 기존 공부를 표시한다.
- Study는 시작 시각과 현재 시각의 차이를 표시한다. 1초 간격 타이머는 화면 갱신 용도이며, 경과시간을 `+1`로 누적하지 않는다.
- 일시정지와 시간 프리셋은 없다. 앱을 나가거나 내 방으로 돌아가도 세션을 종료하지 않는다.
- 공부 끝내기는 저장이 성공한 뒤 `/study-result/[sessionId]`로 화면을 교체한다. 저장 실패 시 세션을 유지하고 재시도할 수 있다.
- 결과 화면은 저장된 결과를 조회한다. URL에 재화나 시간을 넣어 보상을 결정하지 않는다.
- 내 방으로 돌아올 때 `dismissTo('/')`를 사용하여 종료된 Study 화면이 현재 Stack에 남지 않게 한다.
- Study·StudyResult는 `(tabs)` 밖의 루트 Stack에 있어 하단 탭을 표시하지 않는다.
- 진행 중 세션 없이 Study에 직접 접속하거나 존재하지 않는 결과를 열면 내 방 복귀를 안내한다. 새 세션이나 보상을 만들지 않는다.

초기 구현 당시에는 전용 Study 시안이 없어 Home 시안의 하늘색 배경·네이비 외곽선·크림 카드·노란 버튼과 방·캐릭터를 재사용했다. 결과는 인정 공부시간과 Bolt·XP, 발생한 보너스·버그 퇴치 결과만 표시한다. 이후 2026-11-02에 Study·보상 화면을 포함한 v4 목업을 전달받았으며, 다음 UI 작업에서는 [갱신된 디자인 기준](ui-design.md)을 적용한다.

## 계층

```text
HomeRoute / StudyScreen / StudyResultScreen
  → StudyProvider / useHome / useStudyResult / useElapsedTime
  → HomeService / StudyService
  → createMockStudyBackend
  → AsyncStorage / 연결 상태 어댑터
```

- `src/types/study.ts`: 화면용 세션·결과·서비스 타입. Backend DTO가 아니다.
- `src/state/study-context.tsx`: 앱 시작 및 foreground 복귀 시 복구, 중복 요청 제어, Home 갱신 신호.
- `src/services/study.ts`, `src/services/home.ts`: 실제 API로 교체할 서비스 경계.
- `src/services/mock-backend.ts`: Expo 모듈과 초기 Mock 데이터를 주입하는 연결부.
- `src/mocks/study-backend.ts`: UI와 독립된 로컬 Mock 저장·정산 로직.
- `src/utils/study-time.ts`: KST 04:00 서비스 날짜와 시간 구간 분리.

AsyncStorage `2.2.0`과 expo-network `~58.0.4`는 설치된 Expo SDK 58 권장 버전으로 추가했다. 연결 상태 조회에는 IP 조회 등 외부 서비스를 호출하는 기능을 사용하지 않는다.

## Mock의 처리 범위

- 세션·결과·잔액·날짜별 누적시간·버그 퇴치 진행을 AsyncStorage의 `@tamagochi/mock-study/v1` 레코드에 함께 저장한다.
- 신규 시작은 연결 상태 확인 후 허용한다. 복구와 기존 세션 조회는 연결 확인 없이 가능하다. Mock 종료는 로컬 저장으로 처리한다.
- 같은 어댑터 인스턴스의 요청은 순서대로 처리한다. 중복 시작은 기존 세션을, 중복 종료는 기존 결과를 반환한다.
- 저장에 실패하면 성공으로 응답하지 않는다. 손상된 레코드는 오류로 알리고 자동 삭제·초기화하지 않는다.
- 경과시간은 실제로 흐른 시간을 표시하고, 인정시간은 최대 12시간이다. Mock은 시작 후 첫 12시간을 인정 구간으로 사용한다.
- Bolt·기본 XP는 세션별 인정시간의 완전한 분만 계산한다. 일일 누적시간과 버그 진행은 밀리초를 보존하고, 표시할 때 초 단위로 내린다.
- KST 04:00을 지나는 구간은 각 서비스 날짜로 분리한다. 출석 30분·기본 목표 3시간 보너스는 각 날짜별 최초 달성 시 한 번 지급한다.
- 버그가 있는 동안의 인정 공부시간을 누적하고, 60분마다 한 마리를 제거한다. 퇴치 진행은 날짜가 바뀌어도 유지한다.
- 종료 후 Home은 같은 저장 데이터를 다시 읽어 Bolt·오늘 공부시간·출석·버그 상태를 갱신한다.

## API 연동 시 남은 사항

이 구현은 한 기기의 Mock이며, 실제 계정·여러 기기 간 세션 동기화나 서버의 단일 세션 보장을 대신하지 않는다. Web의 여러 탭 간 동시 쓰기 잠금도 제공하지 않는다. 해당 보장은 Backend의 사용자별 활성 세션 조회·생성·종료 계약으로 연결해야 한다.

Mock은 기기 시계를 사용한다. 실제 API에서는 서버 시작 시각과 서버에서 받은 경과시간, 인정시간·보상 결과를 사용하며 UI에서 정산하지 않는다. 2026-11-02에 Backend의 `openapi.yaml`과 구현을 확인했다. 실제 연동은 아직 적용하지 않았으며, 확정된 경로와 Mock의 차이·오프라인 종료 처리 조건은 [UI·백엔드 검토](ui-backend-review.md)를 참고한다.

레벨별 XP 구간을 추측하지 않으므로 Mock의 레벨업은 계산하지 않는다. 미출석 Heart 감소·새 버그 생성, 목표시간 변경과 계정별 저장 정책은 각 기능 및 API 연동 단계의 범위다. Mock의 초기 Heart·Level은 유지한다.

## 검증

```bash
npm run typecheck
npm run lint
npm test
```

Node 기본 테스트 러너를 사용하며 별도 테스트 패키지는 추가하지 않는다. `tsconfig.tests.json`으로 UI 의존성이 없는 Mock과 시간 함수를 `.expo/tests/`에 빌드한다.

주요 테스트는 04:00 경계와 밀리초 보존, timestamp 기반 시간 계산, 중복 시작·종료, 오프라인 차단, 재실행 복구, 분 미만 보상 제외, 초 누적 출석, 보너스 중복 방지, 12시간 상한, 날짜를 넘는 버그 진행, 저장 실패 및 손상 기록 보존이다.

수동 검증은 내 방 → 시작 → Study 새로고침/앱 재실행 → 종료 → 결과 새로고침 → 내 방 순서로 진행한다. 오프라인 신규 시작 차단, Study·결과 화면의 탭 숨김, 0초 세션 종료, 잘못된 결과 URL에서 보상 불변도 확인한다.

개발 중 결과 URL 새로고침에서 Metro의 `Requiring unknown module` 오류가 한 차례 발생했다. `npm start -- --clear`로 모듈 캐시를 재생성한 뒤 Home·Study·결과 URL 12회 요청과 전체 브라우저 흐름 검증이 통과했다. 같은 개발 서버 오류가 나타나면 서버를 종료하고 이 명령으로 다시 실행한다.
