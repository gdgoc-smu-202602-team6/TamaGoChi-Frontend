# 계정 탈퇴와 마이 보유·장착 표시

## 화면과 계약

2026-11-04(KST), Backend `98441b9`의 UsersController·UserRepository와 users/members e2e 계약을 확인했다. 이전 개인 설정 PR은 main에 병합되어 `feat/account-and-inventory`를 최신 main에서 시작했다. 기존 마이의 하늘색 배경·네이비 외곽선·크림색 안내 카드·노란 버튼과 공통 확인창을 재사용하며 패키지를 추가하지 않았다.

API 모드의 마이 → 내 계정 → `계정 탈퇴 안내`에서 `/account-delete`를 연다. 삭제 범위와 계정 닉네임·이메일을 확인한 뒤 별도 확인창의 `계정 삭제 확인`을 눌러야 요청한다. 인증 복구를 기다리고, 로그인하지 않은 직접 접근은 로그인 화면으로 이동한다. AuthProvider에 결과를 보관해 탈퇴 후에도 완료·기기 정리·미확정 결과를 표시하며, 요청 중 Stack 이탈과 중복 탭을 막는다.

본문 없는 `DELETE /users/me`의 성공은 `204`다. 계정·세션·기기 토큰·공부/게임 데이터와 모든 동아리 부원 자격은 서버가 삭제한다. 작성한 공지와 다른 사용자의 방에 남긴 방명록은 작성자 없이 남는다. 어떤 동아리에서든 마지막 `members.manage` 보유자면 `409 last-manager`를 표시하고 세션·로컬 기록을 유지한다. Mock에는 실제 인증 계정이 없으므로 안내만 표시하며 삭제 요청·Mock 데이터 초기화를 제공하지 않는다. 실제 운영 계정을 삭제해 시험하지 않았다.

## 세션·미확정 결과·정리

AuthService의 기존 직렬 큐에서 로그인·복구·로그아웃·삭제·결과 확인을 처리한다. 확인한 사용자 ID와 고정 토큰을 넘기고 현재 저장 토큰과 `GET /users/me`의 ID가 일치해야 DELETE한다. 늦은 이전 계정의 요청/정리가 새 계정 토큰을 취득하거나 삭제하지 않는다.

`204`를 받았을 때만 삭제 완료로 확정한다. 네트워크/timeout·5xx·계약과 다른 성공 응답은 미확정 상태로 잠그고 DELETE를 자동 반복하지 않는다. `탈퇴 결과 다시 확인`은 GET만 보낸다. 같은 계정이 확인되면 새 확인창으로 다시 시도할 수 있다. 401/404 또는 이미 없어진 토큰은 세션 만료와 계정 삭제를 구분할 수 없다고 안내하며 삭제 성공으로 표시하거나 개인 캐시를 삭제하지 않는다. 사전 조회와 삭제를 원자적으로 묶는 조건부 요청 계약은 없다.

확정 후 해당 Backend·사용자 ID의 API 공부 복구, 동아리 선택·이름 캐시, 동아리 생성/공지 작성/방명록 전송 의도를 제거하고 토큰을 지운다. 정확한 키 또는 `/` 경계 안의 하위 키만 선택하며 다른 사용자·다른 Backend·Mock 기록은 보존한다. 서버 삭제 후 기기 저장소 정리 실패는 기존 게임 scope를 닫고 `기기 기록 정리`만 재시도한다. 이 재시도와 foreground 복구는 DELETE를 보내지 않는다.

삭제 영수증·미확정 상태는 현재 실행의 메모리에 유지한다. 앱을 완전히 종료하면 별도 영속 영수증을 복원하지 않는다. 재실행의 일반 인증 복구가 401 토큰을 정리하며 삭제 완료를 추정하거나 DELETE를 재생하지 않는다. 실계정·실기기와 앱 종료 중 정리 흐름은 추가 검증 대상이다.

## 마이의 보유 수량·장착

기존 RoomService의 `GET /items`, `/users/me/items`, `/users/me/room`으로 기본 지급을 포함한 고유 보유 수를 표시한다. 보유 목록에 없는 장착·중복 ID·알 수 없는 아이템·기본 보유 누락 등 불일치는 오류로 처리한다. 방 꾸미기와 같은 인벤토리로 이동하며 새 구매·장착 API는 추가하지 않는다.

장착 HEAD·FACE·NECK만 프로필에 표시하고 미장착 보유 장식은 그리지 않는다. `CharacterSprite`로 방과 프로필의 캐릭터·액세서리 위치와 `itemSource`를 공유한다. 최종 에셋은 레지스트리에서 교체할 수 있고 현재는 임시 SVG다. 장착한 이름을 접근성 라벨로 제공한다.

프로필 통계와 별도로 읽어 아이템 조회 오류가 공부 통계·목표 화면을 막지 않는다. 조회 중/실패에는 수량·장착을 확정하지 않고 `확인 중`/`확인 필요`와 재조회 버튼을 제공한다. 화면 진입·앱 복귀·당겨서 새로고침으로 읽으며 이전 조회·계정 scope의 늦은 응답을 버린다. Mock도 기존 공부 저장소의 보유·장착을 읽어 구매/해제가 수량과 프로필에 반영된다.

## 검증과 미리보기

타입·린트, 총 **356개 테스트**, API Android/iOS/Web·Mock Web 번들이 통과했다. 새 16개는 고정 계정/토큰·단일 bodyless DELETE·마지막 관리자·사전 조회 실패·응답 유실/미적용·비정상 성공·401 미확정·로컬 정리 실패/복구·다른 계정 키 보존·복구 직렬화, 기본 보유 수/장착 전용 표시·잘못된 데이터 거절·Mock 구매/해제를 검증한다.

격리 Chrome의 가짜 API로 로그인 가드·취소·마지막 관리자·중복 탭·미적용 후 GET 확인·서버 삭제 후 토큰 제거 실패와 정리만 재시도·계정/Mock 저장소 분리·다른 계정 진입·응답 유실 후 성공 오표시 방지를 확인했다. 보유/장착 갱신·조회 실패에도 통계 유지·320×568/390×844/1280×844 배치를 확인했고, Mock에서 기본 5개 → 목도리 구매 후 6개와 장착, 해제 후 수량 유지와 프로필 갱신, 캐릭터 터치 드래그·완료 전 기록 보존, API 호출 없는 탈퇴 안내를 확인했다. 운영 호출/쓰기는 차단했다.

Android/iOS의 실제 뒤로가기·화면 읽기·SecureStore, 실계정 삭제/기기 토큰 정리와 최종 에셋 정렬은 별도 검증이 남아 있다. Metro 개발 SSR 오류를 해결한 결과는 아니며 미리보기는 공식 export/serve 결과다.

`http://localhost:8082/mypage`에서 보유 수와 장착을 확인한다. `/shop`에서 구입하거나 `/room-edit`에서 장착을 저장한 뒤 마이로 돌아온다. `/account-delete`는 Mock에서 안내만 표시한다. 실제 API 모드의 탈퇴 확인 버튼은 로그인한 실제 계정을 삭제한다.
