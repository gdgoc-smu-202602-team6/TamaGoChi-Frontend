# 공지 읽지 않은 수 배지

## 범위와 디자인

2026-11-04(KST), Backend `98441b9`의 OpenAPI 0.1.0과 공지 조회·읽음 계약을 기준으로 구현했다. 기존 공지 시안의 작은 빨간 숫자 배지를 참고해 하단 공지 탭과 동아리 선택 칩에 적용했다. 네이비 탭·노란 선택 영역·하늘색 배경과 네 개 탭을 유지했다. 공통 탭 파일과 게임 Provider의 수정 범위는 배지 표시·조회 상태 연결이며 라우팅 구조·패키지는 변경하지 않았다.

하단 공지 탭은 **현재 선택한 동아리**의 수를 표시한다. 모든 동아리를 합산하지 않는다. 공지 화면의 선택 칩은 각 동아리의 수를 표시한다. 알림 수신 여부와 읽지 않은 수는 독립적이며 알림을 끈 동아리도 공지를 읽기 전까지 수에 포함한다. 목록 분류 필터와 무관한 동아리 전체 수다.

`GET /clubs/{clubId}/notices?read=false&totalSize=true&pageSize=0`의 서버 `totalSize`만 사용한다. 목록 첫 페이지의 NEW 개수·배열 길이로 추정하거나 본문을 자동 읽음 처리하지 않는다. 0개는 숫자 배지를 숨기고, 100개 이상은 `99+`로 표시한다. 네이티브 탭 접근성 라벨과 웹 탭/동아리 칩의 연결된 설명에는 동아리와 정확한 수를 제공한다. 조회 전·실패는 확인 필요 상태이며 0개로 표시하지 않는다.

Android/iOS는 SDK 58의 `NativeTabs.Trigger.Badge`, Web은 공통 `UnreadBadge`를 사용한다. Web 탭 라벨은 유지하고 `aria-describedby`로 선택 동아리와 실제 수를 전달한다. 320px에서도 `99+`와 라벨이 들어가고 동아리 선택 칩은 기존처럼 가로 스크롤한다. OS 홈 화면 앱 아이콘 배지나 푸시 수신 표시를 구현한 것은 아니다.

## 상태와 갱신

`NoticeUnreadProvider`는 계정별 GameScope의 ClubProvider 안에서 승인된 동아리만 읽는다. 클럽 목록 확인 전/실패·인증 불가 상태에서는 수를 숨긴다. 새 부원 목록 객체를 새 scope로 사용해 같은 동아리 ID로 재가입해도 이전 수가 남지 않게 한다. 동아리 전환 저장 중에는 하단 숫자를 숨기며 선택이 확정되면 해당 동아리 수를 사용한다.

`createNoticeUnreadTracker`는 동아리별 중복 조회를 합치고 전체 조회를 최대 3개씩 실행한다. 한 동아리의 오류가 다른 동아리의 성공 값을 지우지 않는다. 화면의 `읽지 않은 수 다시 확인`으로 다시 읽을 수 있다. 멤버십/계정 scope와 요청 버전을 확인해 이전 응답·실패·대기 작업을 버린다. 조회 실패 시 이전 양수를 남겨 현재 값처럼 표시하지 않는다.

앱 진입·동아리 목록 갱신·공지 화면 진입/새로고침·foreground 복귀와 활성 상태의 60초 주기로 조회한다. 읽음 PUT, 공지 등록·수정·삭제 전후에는 해당 수를 무효화하고 GET으로 확인한다. 처리 도중 시작된 옛 조회도 결과 확인 뒤의 수를 덮지 못한다. 응답 유실 후에도 쓰기 요청을 자동 반복하거나 숫자를 낙관적으로 빼지 않는다. 기존 본문·읽음/작성 상태의 오류 처리는 유지한다.

수는 메모리에만 보관한다. 토큰·본문·새 캐시 키를 추가하지 않으며 Mock은 기존 공지·읽음 저장소와 멤버십을 읽는다. 공부·볼트·장착 기록을 변경하지 않는다. 실시간 서버 이벤트를 수신하지 않으므로 외부 변경은 다음 조회에 반영된다.

## 실제 푸시의 후속 조건

Backend `98441b9`의 PushModule은 아직 `LoggingPushSender`를 연결하고 있어 로그만 남긴다. `/users/me/deviceTokens/{token}` 등록/삭제 계약은 FCM 토큰이지만, 앱에는 알림 모듈·Firebase 모바일 설정·빌드 식별자 설정이 없다. 이번 단계에서 기기 토큰을 등록하거나 실제 발송 성공을 표시하지 않았다.

[SDK 58 알림 문서](https://docs.expo.dev/versions/v58.0.0/sdk/notifications/)의 native token은 Android의 FCM·iOS의 APNs 토큰이다. iOS APNs 토큰이나 Expo Push Token을 FCM 토큰으로 등록해서는 안 된다. 후속 작업은 백엔드 발송 구현과 iOS 토큰 방식을 합의하고 Firebase/앱 식별자·기기 빌드 설정을 준비한 뒤 진행한다. Android 원격 푸시는 Expo Go가 아닌 development build에서 검증해야 한다. 사용자 권한·토큰 회전·로그아웃 삭제·공지/신청 링크 진입·실제 발송/수신은 남아 있다.

## 검증과 미리보기

타입·린트와 총 **370개 테스트**, API Android/iOS/Web·Mock Web 번들이 통과했다. 새 14개는 배지/정확한 설명·0/미확정 구분·동아리 분리·잘못된 수/부분 실패·중복 조회·변경 전 응답 무시·재가입 scope·탈퇴/미승인 제외·동시 조회 상한·계정 전환과 대기 중단·재시도·외부 저장소 구독·정확한 API 쿼리·Mock 읽음 저장/실패를 확인한다.

운영 API를 차단한 격리 Chrome에서 선택 동아리 수와 합계의 구분·동아리 칩·필터 무관성·99+와 실제 수 설명·부분 실패/재조회·미적용 읽음/응답 유실·0개 숨김·늦은 동아리/계정 응답·탈퇴한 동아리 제외·세션 만료를 확인했다. Mock은 읽음 후 감소·동아리별 분리·새로고침 영속성·공지 등록 후 증가/삭제 후 감소·공부 기록 보존·운영 호출 0회를 확인했다. 320×568·390×844·1280×844 화면을 확인했다. 실제 Android/iOS 화면 읽기·네이티브 배지·foreground와 푸시 수신은 실기기 검증이 남아 있다.

`http://localhost:8082/notice`에서 확인한다. 본문을 펼친 뒤 하단 공지 탭과 동아리 칩의 수가 함께 바뀐다. 기존 브라우저의 읽음·탈퇴/재가입 기록에 따라 수는 달라진다. 이 단계는 공식 export/serve로 검증했으며 이후 Metro 개발 SSR 오류의 수정과 개발 실행 방법은 [안정화 작업](metro-dev-stability.md)에 정리했다.
