# 방 꾸미기·실제 장착 상태 표시

## 화면과 범위

초기 바닥 구현은 2026-11-03 Backend `98441b9`를, 2026-11-04 면 배치 확장은 Backend `01ace7c`의 실제 Room/Placement/PlacementPolicy와 OpenAPI를 확인했다. 사용자 기능 명세와 기획 v4 `10-decor`의 큰 등각 방, 선택 테두리, 크림색 인벤토리, 가구·벽지·캐릭터·방 확장 분류, 초기화·상점·완료 진입을 사용했다. 기존 공통 테마·노란 버튼·카드·아이템 미리보기를 재사용했다.

내 방의 `방 꾸미기` 또는 마이의 `보유 아이템 · 방 꾸미기`에서 `/room-edit`를 연다. 인증이 필요한 루트 Stack 화면이며 하단 탭은 숨긴다. 보유한 카탈로그 아이템만 장착·해제하며 같은 슬롯은 교체한다. ROOM은 해제하지 않고 다른 보유 방으로 교체한다. 선택·드래그·위치 초기화는 편집 중 미리보기이고, **완료를 눌렀을 때만 저장**한다. 상점에서는 별도의 구매 API로 구매 즉시 장착하는 기존 계약을 유지한다.

물건을 직접 터치한 채 끌어서 옮긴다. 선택한 물건은 분홍 점선과 이름으로 표시한다. 사용자 피드백을 반영해 좌표 숫자·X/Y 이동 버튼·배치 대상 선택 목록을 제거하고, 방 바로 아래에 드래그 안내와 위치 초기화를 배치했다. 작은 물건도 쉽게 잡을 수 있도록 터치 영역을 최소 44dp까지 확장한다. 마우스 드래그도 같은 방식으로 동작한다.

이미지 자체의 브라우저 드래그를 막기 위해 객체의 그림은 입력을 받지 않고 바깥 배치 컨테이너가 터치를 처리한다. 물건을 끄는 동안 목록 스크롤·다른 편집 버튼을 막고, 터치가 중단되면 끌기 시작 위치로 복원한다. 좌표 변환은 내부 구현이며 일반 화면에 노출하지 않는다.

## API와 검증

| 요청 | 용도 |
| --- | --- |
| `GET /items` | 코드·슬롯·분류·방 크기 등 현재 카탈로그 |
| `GET /users/me/items` | 기본 보유를 포함한 보유 ID |
| `GET /users/me/room` | 장착 전체·배치·사용자 상태 |
| `PATCH /users/me/room` | 장착·배치만 전송. 새 계약은 배치마다 `surface` 포함, 이전 계약은 기존 target/x/y 유지 |

카탈로그·보유 ID 파서는 기존 상점과 공유한다. UUID·슬롯·카테고리·중복 ID·금액·방 크기·소유권, ROOM 필수·슬롯 중복·아이템 슬롯 일치, 배치 대상·중복·유한 좌표·범위·반 칸 정렬을 확인한다. 응답의 사용자 ID도 현재 계정과 일치해야 한다. 누락·잘못된 상태를 임의 가구나 Mock으로 대체하지 않는다.

장착 가능한 대상의 배치만 보낸다. 새 계약의 Room `wallHeight: 3`과 아이템별 정책이 확인되면 시계·창문을 벽에서 직접 드래그한다. 스탠드는 정책이 없어 고정 위치, 머리·얼굴·목 장식은 캐릭터에 붙인다. 이전 계약은 기존 바닥 대상과 고정 시계·창문을 유지한다. Heart·Bug·좋아요·방명록 확인 시각·읽기 전용 벽 높이는 꾸미기 본문에 넣지 않는다.

## 좌표와 방 크기

아래 초기 바닥 좌표 설명은 이전 계약에 해당한다. 새 계약은 대상의 크기 사각형·카탈로그 간격·면 종류와 같은 면 solid 충돌을 검증한다. 방 확장 시 벽 y는 유지한다. 실제 변환·정책·기존 명세와 다른 겹침 제한·운영 반영 조건은 [바닥/벽 배치 계약](room-wall-placement-contract.md)을 참고한다.

- 서버 배치는 바닥 칸 단위의 0~n 좌표다. DESK·BOOKSHELF는 0.5칸에 맞추고, PLANT·RUG·CHARACTER는 자유 좌표를 사용한다. 끌기에서 자유 좌표는 소수점 넷째 자리로 정리한다. 물건 사이 충돌 제한은 추가하지 않는다.
- `utils/room-layout.ts`가 화면 크기와 독립적인 등각 좌표·역변환·드래그 이동을 담당한다. 뷰포트 픽셀을 API 좌표로 그대로 보내지 않는다. 다른 화면 너비에서도 같은 비율의 이동이 된다.
- 그림의 발밑/바닥 선과 여유 폭은 placeholder 메타데이터로 분리했다. 논리 좌표는 0~n으로 유지하면서 그려진 바닥 안에 물건의 밑면이 들어가도록 변환한다. 캐릭터의 발과 러그의 중심 기준선이 다르다. 최종 에셋에는 해당 크기·기준선·여유 폭을 맞춰야 한다.
- 방 교체 시 저장된 배치는 새 크기의 비율로 이동하고 대상별 그리드·범위에 맞춘다. 해제된 가구의 배치는 제거하고 같은 슬롯 교체는 위치를 유지한다. 좌표가 없는 대상은 공통 기본 위치를 사용한다. `위치 초기화`는 배치 목록을 비우며 장착·보유 아이템은 바꾸지 않는다.

## 저장·이탈·동시 변경

저장 직전 현재 카탈로그·소유권·방을 다시 읽는다. 이미 원하는 배치가 저장되어 있으면 PATCH하지 않는다. 편집 시작 때와 다른 방이면 덮지 않고, 편집 내용을 유지한 채 서버 방을 다시 불러오도록 안내한다. 선택한 장착 아이템이 더 이상 보유 목록에 없을 때도 저장을 막는다.

네트워크·타임아웃·5xx·잘못된 성공 응답 뒤에는 읽기로 저장 결과를 한 번 확인한다. 원하는 배치가 확인되면 성공으로 복구하고, 확인되지 않으면 편집 내용을 유지하며 쓰기를 잠근다. `저장 상태 다시 확인`은 GET만 사용한다. 원하는 배치가 확인되면 완료 상태로, 원래 서버 방이 유지되어 있으면 사용자가 직접 다시 완료를 누를 수 있는 상태로 돌아온다. 자동 PATCH 재전송은 없다.

화면 진입·foreground 복귀 때 다시 읽는다. 편집하지 않은 상태라면 최신 서버 방을 표시하고, 수정 중이면 초안을 덮지 않고 변경 여부를 확인한다. 명시적 `서버 방 다시 불러오기`에는 현재 편집을 버리는 확인을 둔다. 저장 전 내 방·상점 이동이나 뒤로 가기는 Expo Router SDK 58의 `usePreventRemove`로 확인한다. Web 새로고침·창 닫기의 기본 이탈 확인도 같은 훅을 사용한다. 저장 중에는 중복 완료·이동을 막는다.

방 API에는 ETag/If-Match 계약이 없다. 전송 직전 확인 이후 다른 기기가 수정한 경우까지 원자적으로 막지는 못하며 서버의 마지막 저장이 적용된다. 다른 기기에서 보낸 요청을 취소하거나 새로운 서버 버전 계약을 가정하지 않는다. 초안은 현재 화면 메모리에만 있으며 강제 종료 후에는 서버 방을 다시 읽는다. 별도의 오프라인 편집 자동 저장·재전송은 추가하지 않았다.

## 공통 렌더링과 에셋

Home·Study·결과·꾸미기는 같은 `RoomScene`을 사용해 실제 장착 아이템과 저장된 배치를 표시한다. Home도 카탈로그·보유 목록을 읽으며 화면 복귀·foreground와 게임 데이터 갱신 때 다시 조회한다. 늦게 끝난 이전 Home 조회는 최신 응답을 덮지 않는다.

`features/shop/assets/item-assets.ts`의 `Item.code` 레지스트리를 상점·방이 공유한다. 등록되지 않은 아이템은 슬롯별 임시 SVG다. `features/room/assets/room-shell.ts`의 방에는 가구·시계·창문이 박혀 있지 않아 해제 상태가 그림에 반영된다. 벽지는 현재 임시 코드별 색상, 방 확장은 공간 대비 물건 크기로 표현한다. 실제 아트워크의 등각 원근·가구 발밑·캐릭터 장식 정렬과 마이 프로필 캐릭터의 장착 표현은 최종 에셋 단계에 조정해야 한다.

상점·인벤토리 썸네일의 타원 그림자는 배치 맥락과 구분한다. 방에서는 책상·책장·화분 아래에만 사용하고, 벽의 시계·창문·스탠드, 캐릭터 장식과 러그에는 붙이지 않는다.

예전 Home 전용 고정 에셋은 명시적 Home 미리보기 입력과의 호환용으로 남아 있으며, 실제 API·Mock Home 서비스는 장착 기반 appearance를 제공한다.

## Mock과 기록 보존

기존 `@tamagochi/mock-study/v1`의 shop 장착 목록과 placements를 사용한다. 앱의 Mock 미리보기는 새 면 배치이며 이전 기록은 읽을 때만 변환한다. 명시적 저장/구매 때 같은 저장소에 배치 버전 2를 남기고 공부 기록을 보존한다. 손상을 숨기는 이관이나 읽기 중 쓰기는 하지 않는다. 방 저장·구매·공부는 기존 직렬 큐를 공유한다.

방 저장은 장착·배치만 바꾼다. 공부 결과·일별 기록·목표·현재 세션·Bolt·Bug를 바꾸지 않는다. Mock 상점의 새 방 구매도 같은 배치 비율 조정을 적용하며 이미 보유한 아이템 구매는 재장착하지 않는다. 저장 실패·손상 기록은 보존한다.

## 검증과 미리보기

```powershell
npm.cmd run typecheck
npm.cmd run lint -- --no-cache
npm.cmd test
```

좌표·소유권·장착·저장·복구·Mock 보존에 대한 17개를 추가해 총 131개 테스트를 통과했다. Home 계약 테스트도 실제 카탈로그·장착 표시를 확인하도록 갱신했다. 새 라우트 타입은 공식 `expo customize tsconfig.json`으로 생성했다.

Android·iOS·Web 번들을 통과했다. 격리 Chrome의 API fixture로 인증 전 차단, 탭 숨김, 네 분류·장착 교체·해제, 마우스/터치 드래그, 저장 전 쓰기 없음, 이탈 확인, 중복 완료 차단, 내 방 장착 반영·새로고침, 방 확장, foreground 최신 조회, 외부 변경, 응답 유실·조회 복구 실패·읽기 재확인, 위치 초기화, not-owned·계정 전환·만료와 320·390·1280px 배치를 검증했다. 운영 API 쓰기는 0회였다.

Mock에서는 공부 시작·종료 후 장착 해제·드래그·저장, 상점의 화분·방 구매 후 꾸미기·내 방 반영, 저장 실패 시 기록·초안 보존과 조회 재확인, 방 축소·위치 초기화, 마이 진입·외부 변경과 기존 공부 결과·날짜 기록·현재 세션 보존을 확인했다. 운영 호출은 0회였다. 테스트를 위해 격리 저장소의 레벨·잔액을 조정했으며 제품에 데모 배속·재화 지급 버튼은 추가하지 않았다.

직접 드래그로 UI를 단순화한 후 타입·린트·131개 테스트와 Android·iOS·Web 번들을 다시 확인했다. 격리 Chrome에서 좌표·이동 버튼 제거, 마우스 드래그, 작은 물건의 그림 바깥 확장 영역에서 터치 드래그, 완료 전 미저장·완료 저장, 위치 초기화와 320·390·1280px 배치를 확인했다. 실제 기기의 44dp 터치 영역·화면 읽기 동작은 별도 검증 대상이다.

미리보기는 다음처럼 실행한다.

```powershell
$env:EXPO_PUBLIC_DATA_MODE='mock'
npx.cmd expo export --platform web --output-dir .expo/preview
npx.cmd expo serve .expo/preview --port 8082
```

`http://localhost:8082/room-edit`에서 로그인 없이 확인한다. API 모드는 환경 변수를 api로 바꿔 다시 내보내고 로그인한다. 운영 계정의 방은 이번 검증에서 수정하지 않았다. 실제 Android/iOS 터치·뒤로가기/스와이프·접근성·네트워크 전환·동시 기기 저장과 최종 에셋 검증은 남아 있다. 초기 Metro 개발 SSR 오류의 2026-11-04 수정과 개발 서버 실행은 [Metro 안정화](metro-dev-stability.md)를 참고한다.
