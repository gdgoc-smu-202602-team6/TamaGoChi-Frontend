# 닉네임·내 소속·알림 설정

## 화면과 범위

2026-11-04(KST)에 Backend `98441b9`의 Users·Members 컨트롤러, Nickname·Member의 변경 제한, OpenAPI 0.1.0을 확인했다. 기존 마이·동아리 설정 시안의 하늘색 배경·크림색 입력 카드·네이비 테두리·노란 저장 버튼, 파트별 색상과 공통 토글/확인창을 재사용했다. 패키지·에셋은 추가하지 않았다.

마이의 `닉네임 설정`은 `/settings/profile`, 선택한 동아리의 `내 소속·알림 설정`은 `/clubs/{clubId}/preferences`로 이동한다. 가입 목록의 각 동아리 카드에도 내 설정 진입을 제공한다. 모두 인증된 루트 Stack 화면이다. 관리 권한과 관계없이 현재 본인의 부원 자격이 있어야 동아리 설정을 사용할 수 있다.

이 단계는 닉네임과 내 소속 파트·동아리 공지 알림 수신 설정을 구현한다. 계정 탈퇴, 마이의 보유 아이템 수·장착 표현은 개인 설정의 다음 단계로 남아 있다. 이 알림 설정 저장이 실제 기기 푸시 권한·토큰 등록이나 발송 검증 완료를 의미하지는 않는다.

## API와 변경 필드

| 요청 | 용도 |
| --- | --- |
| `GET /users/me` | 현재 계정·닉네임 |
| `PATCH /users/me` | `{ nickname }`만 변경 |
| `GET /clubs/{clubId}/members/me` | 현재 내 부원 자격·파트·`notificationsOn` |
| `GET /clubs/{clubId}`, `/parts` | 동아리 이름과 현재 파트 목록 |
| `PATCH /clubs/{clubId}/members/{memberId}` | 실제 바꾼 `partId`·`notificationsOn`만 변경 |

계정 ID는 로그인한 사용자와 일치하는지 검증한다. 닉네임은 앞뒤 공백을 제거한 1~10 grapheme cluster이고 중복을 허용한다. UTF-16 입력 길이로 이모지를 자르지 않으며 Segmenter가 없는 런타임에서는 서버의 최종 길이 검사를 따른다. 변경 후 계정 정보를 재조회하고 AuthProvider의 계정 메타데이터도 갱신한다. 같은 사용자/토큰이면 기존 게임 세션 scope를 바꾸지 않는다.

동아리 설정은 내 부원의 계정·동아리·UUID·가입 시각, 필수 boolean 알림 값·동적 파트와 현재 파트 관계를 검사한다. 역할·관리 권한을 조회하지 않으며 역할 ID를 PATCH하지 않는다. 파트만 바꾸면 `partId`만, 알림만 바꾸면 `notificationsOn`만 보낸다. 두 값을 바꾸면 둘만 보낸다. `me` 대신 확인한 구체적인 부원 UUID로 수정해 늦은 요청이 새로 가입한 자격에 적용되지 않게 한다.

## 원본·오류·초안

화면을 열었을 때의 원본과 입력을 별도로 보관한다. 재조회나 foreground 갱신이 작성 중인 값을 자동으로 대체하지 않는다. 저장 직전에 현재 값을 읽어 원본과 비교하고 외부 닉네임/파트/알림/역할 변경, 사라진 선택 파트, 다른 부원 ID나 가입 시각을 감지하면 쓰기 없이 다시 확인하도록 한다. `현재 값으로 입력`을 눌러 새 원본을 명시적으로 채택할 수 있다.

같은 값이 이미 적용돼 있으면 추가 PATCH 없이 현재 값을 반환한다. 중복 탭과 변경 요청은 화면과 서비스에서 직렬화한다. 조회는 독립적으로 실행해 이전 화면의 느린 조회가 다른 동아리 설정을 막지 않는다. 현재 값과 응답의 계정/대상·요청 필드를 검증하고 다시 읽어 실제 결과를 확인한다.

확정된 4xx는 재전송하지 않는다. 네트워크·타임아웃·5xx·잘못된 성공 응답은 GET으로 확인하며 PATCH를 자동 반복하지 않는다. 미적용·재조회 실패는 기존 입력을 읽기 전용으로 두고 `설정 다시 확인`을 안내한다. 이 버튼은 GET만 수행한다. 저장 결과 확인 중 재가입한 자격이 나오면 이를 이전 요청의 성공으로 표시하지 않는다. ETag/조건부 수정 계약이 없으므로 사전 조회 이후의 서버 동시 변경까지 원자적으로 막는 기능은 아니다.

초안이 있는 Stack 이탈은 확인창을 표시하고 저장 처리 중에는 제거를 막는다. 브라우저 전체 페이지 이동을 차단하는 기능은 아니며 입력이나 미확정 PATCH를 로컬에 보관/재전송하지 않는다. 계정 전환·401/403/404에서는 이전 내용과 입력을 제거한다. 다른 계정이나 동아리로 이동한 뒤 도착한 이전 응답도 적용하지 않는다.

## Mock 공유

닉네임은 `@tamagochi/mock-account-settings/v1`의 `{ version: 1, nickname }`에 저장한다. 저장한 이름이 있으면 기존 공부 서비스 결과 위에 표시값을 합쳐 내 방·마이에서 사용하고, 모든 동아리의 내 부원 목록에서도 같은 이름을 사용한다. 저장 전에는 기존 데모의 표시값을 유지한다. 공부 서비스의 원래 레코드와 정산 로직을 변경하지 않는다.

파트·알림은 `@tamagochi/mock-member-preferences/v1`의 `{ version: 1, members: [{ id, clubId, userId, joinedAt, partId, notificationsOn }] }`에 저장한다. 정확히 같은 부원 자격에만 적용하므로 탈퇴 후 승인된 새 자격은 이전 알림 설정을 물려받지 않는다. 역할 변경/강퇴/파트 추가·삭제와 같은 저장소별 변경 잠금을 사용하며 역할 기록을 다시 쓰지 않는다. 현재 부원 목록의 파트에도 적용하므로 사용 중 파트 삭제 제한과 친구/방명록의 이름 표시가 같은 데이터를 사용한다.

조회만으로 초기 설정을 저장하지 않는다. 저장 실패·손상 시 기존 기록을 삭제하거나 기본값으로 덮지 않는다. 다른 동아리 설정·공부·볼트·장착·좋아요·방명록 레코드를 변경하지 않는다. 초기 데모의 알림은 켬이며 새 부원 자격도 켬으로 시작한다.

## 검증

타입·린트와 총 **340개 테스트**, API Android/iOS/Web·Mock Web 번들을 확인했다. 새 19개는 Unicode 닉네임·계정/DTO 검증·실제 변경 필드·중복/외부 변경·재가입 전후 자격·응답 유실/미적용/권한 회수·동아리 격리, Mock 영속성·파트 삭제 참조/동시 저장·역할/개인 기록 보존·재가입 기본 설정·저장 실패/손상을 검증한다.

격리 Chrome에서 API 응답 주입과 Mock 검증을 통과했다. 인증 진입·초안 이탈 확인·중복 저장·닉네임 반영·변경 필드만 전송·외부 변경/파트 삭제 차단·응답 유실 후 GET 확인·미적용 자동 재전송 방지·재가입 전후 자격 분리·늦은 조회/동아리/계정 격리·권한 회수/세션 만료를 확인했다. Mock에서는 재접속·내 부원 목록 파트 반영·저장 실패 후 명시적 입력 복원·재가입 기본 알림과 닉네임 유지·공부/역할 기록 보존도 확인했다. 공유 변경 잠금을 사용하는 기존 파트 추가/삭제 화면의 회귀 검증도 통과했다.

320×568·390×844·1280×844에서 가로 넘침 없이 표시됨을 확인하고 320 화면의 버튼 문구를 다듬었다. 운영 API 호출/쓰기는 차단한 상태로 검증했다. 실제 계정·Android/iOS 키보드/뒤로가기·화면 읽기와 실제 기기 알림 발송 검증은 별도다.
