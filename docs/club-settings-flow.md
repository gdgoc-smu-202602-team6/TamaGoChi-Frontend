# 동아리 기본 설정

## 범위와 디자인

2026-11-03(KST)에 Backend `98441b9`의 Clubs 컨트롤러·저장소·ClubName 도메인·e2e와 OpenAPI 0.1.0을 확인했다. v4 `24-club-admin`의 동아리 요약 카드, 부원 수, 크림색 초대 코드 영역과 복사·재발급 버튼을 사용한다. 하늘색 배경·네이비 테두리·노란 주요 버튼과 공통 입력·확인창을 재사용한다. 시안의 예시 코드 대신 계약의 영문 대문자·숫자 8자리를 표시한다.

공지와 마이에서 현재 선택 동아리의 `동아리 기본 설정`을 연다. `club.update` 권한으로 진입 버튼을 표시하고 클릭 직전에도 다시 확인한다. 공지 작성·분류 관리·가입 신청 처리 권한만으로는 사용할 수 없다. `/clubs/{clubId}/settings`는 인증이 필요한 루트 Stack 화면이며 하단 탭을 표시하지 않는다. 직접 주소로 접근해도 권한 확인 전에 초대 코드를 요청하지 않는다. 부원 권한·파트·탈퇴·강퇴는 이번 화면에 추가하지 않았다.

## 이름과 초대 코드

| 요청 | 용도 |
| --- | --- |
| `GET /clubs/{clubId}/members/me/permissions` | 현재 `club.update` 권한 확인 |
| `GET /clubs/{clubId}` | 현재 이름·부원 수·초대 코드·생성일·ETag |
| `PATCH /clubs/{clubId}` | `{ name }`만 전송, 읽을 수 있는 ETag를 `If-Match`로 전달 |
| `POST /clubs/{clubId}:regenerateInviteCode` | 본문 없이 새 코드 발급 |

이름은 앞뒤 공백을 제거한 1~20 grapheme cluster다. `Intl.Segmenter`가 없는 환경에서는 최대 길이를 서버가 검증한다. 이미 현재 이름과 같으면 PATCH 없이 현재 설정을 반환한다. 편집을 시작한 원본을 별도로 유지하므로 foreground 재조회가 새 이름을 받아도 작성 중인 이름으로 외부 변경을 덮어쓰지 않는다. 원본 이름·코드·ETag가 달라졌거나 서버가 412를 반환하면 현재 설정을 확인한 후 `현재 이름으로 되돌리기`로 입력을 맞춘다.

Web에서 CORS 설정 때문에 ETag를 읽을 수 없으면 버전 값을 만들지 않는다. 변경 직전 최신 이름·코드 비교를 수행하고 If-Match 없이 계약의 PATCH를 사용한다. 이 경우 조회와 PATCH 사이의 동시 변경까지 클라이언트가 막을 수는 없다. 재발급 POST에는 조건부 요청 계약이 없으므로 최신 원본 비교는 하되 임의의 If-Match를 추가하지 않는다.

초대 코드는 선택 가능한 Text와 `초대 코드 복사` 버튼으로 제공한다. SDK 58에 맞는 공식 [expo-clipboard](https://docs.expo.dev/versions/v58.0.0/sdk/clipboard/) `~58.0.4`를 Expo 설치 명령으로 추가했다. 버튼 탭에서 바로 `setStringAsync`를 호출하며 클립보드를 읽지 않는다. 실패하면 코드 선택·길게 누르기 복사를 안내한다.

재발급은 동아리 이름과 이전 코드의 즉시 무효화를 안내하는 확인창을 거친다. 확인 시 원본을 보관해 확인창이 열린 동안 다른 운영진이 바꾼 코드로 재발급하지 않는다. 재발급 결과는 목록을 다시 읽어 표시하고 이전 코드는 서버가 즉시 무효화한다. 기존 부원 자격이나 대기 신청을 취소하지 않는다.

## 결과·실패·계정 격리

화면과 서비스에서 중복 요청을 직렬화한다. 성공 응답도 클럽 ID·이름·코드·생성일·부원 수·ETag를 검증하고 현재 권한과 설정을 다시 읽는다. 확정된 4xx는 쓰기를 반복하지 않는다. 네트워크·타임아웃·5xx·잘못된 성공 응답은 현재 이름 또는 이전과 달라진 코드를 조회해 확인한다. 다른 운영진이 같은 상태를 만들 수 있으므로 내가 변경했다고 추정하지 않고 “현재 설정에서 처리 상태를 확인했어요”로 표시한다.

결과를 확인하지 못하면 입력과 마지막 설정을 유지하고 변경·복사 기능을 잠근다. `설정 다시 확인`은 GET만 수행한다. 새 목록에서도 이전 코드가 유지되면 사용자가 결과를 검토하고 재발급을 명시적으로 다시 선택한다. 재발급 확인창은 다시 표시하며 새 요청이 현재 코드를 무효화한다는 안내를 유지한다. 서버에는 idempotency key가 없고, 이전 요청이 취소됐다고 보장하지 않는다. 새로고침·재실행은 현재 설정만 읽고 쓰기를 자동 재전송하지 않는다.

API 모드의 코드·초안·미확정 요청은 AsyncStorage에 저장하지 않는다. 화면을 벗어나면 저장하지 않은 이름 입력은 유지하지 않는다. 권한 상실·인증 만료 시 초대 코드·입력·열린 확인창을 제거한다. 기존 계정별 서비스 scope와 고정 Bearer 클라이언트가 다른 계정의 늦은 응답을 차단한다.

변경이 확인되면 공통 가입 목록도 갱신해 뒤로가기로 돌아와도 새 이름을 표시한다. `공지 목록으로`는 현재 소속과 동아리 선택 저장까지 확인한 뒤 이동한다. 분류·공지·공부 데이터는 설정 변경으로 수정하지 않는다.

## Mock과 검증

Mock 설정은 `@tamagochi/mock-club-settings/v1`의 `{ version: 1, clubs: { [clubId]: { name, inviteCode, revision } } }`에 저장한다. 기록이 없으면 기존 동아리·초대 코드와 생성 기록을 유지한다. 조회만으로 기본 기록을 쓰지 않는다. 공지·가입 목록·신청 동아리 이름·초대 코드 검색·생성 결과 복구가 같은 설정을 읽는다. 재발급한 옛 코드로는 검색되지 않고 새 코드로 동일 ID의 동아리를 찾는다. 다른 동아리·기존 공부·공지·신청·부원 자격 기록은 변경하지 않는다. 손상된 기록과 저장 실패를 알리며 지우거나 성공으로 처리하지 않는다.

타입·린트와 총 225개 테스트가 통과했다. 새 19개는 정확한 권한·DTO·ID·이름 길이, ETag 전달과 미노출 대응, 변경 필드·중복 요청·사전 충돌·412, 본문 없는 재발급, 응답 유실·잘못된 성공 응답·미적용·재조회 실패·권한 회수, Mock 이름 공유·코드 무효화·생성 결과 복구·저장 실패·손상 보존을 검증한다. API Android·iOS·Web과 Mock Web 내보내기도 통과했다.

격리 Chrome의 가짜 API로 인증 제한·정확한 권한, 이름 검증·중복 저장·뒤로가기 후 목록 반영, 가짜 클립보드 성공·실패, 재발급 취소·중복 탭·재실행, 편집 중 외부 변경·확인 중 코드 변경·412, 응답 유실·잘못된 응답·조회 실패 후 수동 확인, 계정 전환·인증 만료·권한 회수 시 확인창 제거를 확인했다. Mock에서는 새 이름과 코드의 저장·검색, 이전 코드 차단, 공지/마이 진입, 저장 실패 후 입력 보존·수동 재시도, 일반 부원 제한·새 동아리 운영자·생성 결과 갱신·동아리 격리·공부 기록 보존을 확인했다. 320·390·1280px에서 가로 넘침을 확인했다. 공통 Mock 변경 후 기존 가입 신청·취소·승인 후 공지 진입 브라우저 검증도 통과했다.

운영 API 네트워크를 차단하고 가짜 클립보드를 사용했다. 운영 동아리 이름이나 코드를 변경하지 않았다. 실제 계정의 재발급·여러 기기의 동시 수정·실기기 클립보드·키보드·화면 읽기는 별도 검증이 필요하다.

미리보기: `http://localhost:8082/notice`의 첫 동아리에서 `동아리 기본 설정`을 누른다. 직접 주소는 `/clubs/mock-club-study/settings`다. 두 번째 Mock 동아리는 일반 부원이므로 진입 버튼이 없다. 실제 API에서는 해당 동아리의 `club.update` 권한이 필요하다.

후속 [파트 관리](club-parts-flow.md)를 별도의 `parts.manage` 권한으로 연결했다. 기본 설정 화면의 진입도 이 권한을 독립적으로 확인한다.
