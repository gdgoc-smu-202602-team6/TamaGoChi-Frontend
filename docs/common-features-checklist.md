각 기능의 이전 브라우저 검증 기록을 유지하고 이번 마무리에서는 새 방 계약에 영향을 받는 공통 렌더러와 핵심 사용 흐름을 다시 확인한다. 기존 단위 테스트와 새 면 배치 15개를 합한 388개 테스트를 사용한다.

## 이번 마무리 검증

- 타입 검사·린트·388개 테스트와 API Android/iOS Hermes·Web SSR, Mock Web SSR 내보내기를 통과했다. 네이티브 설치 파일 생성/기기 실행을 검증한 결과는 아니다.
- 격리 Chrome의 Mock에서 시계/창문 마우스·터치 드래그·반대 벽 이동·완료 전 기록 불변·저장 후 재진입·홈 반영·위치 초기화를 확인했다. 단순 터치와 기본/저장 위치의 터치 취소는 불필요한 미저장 변경을 남기지 않는다.
- 같은 Mock 흐름에서 진행 중인 공부 보존·동일 세션 복귀·결과 1회·상점 구매·마이 갱신을 확인했다. 기존 공부/재화/결과를 방 저장으로 바꾸지 않았다.
- API 모드의 가짜 응답으로 인증 가드·면 포함 PATCH 1회·읽기 전용 필드 제외·응답 유실/후속 조회 실패 뒤 GET 복구·계정 전환·이전 계약·인증 만료 후 쓰기 방지를 확인했다. 작은 방과 확장된 방을 사용했다.
- 320×568·390×844·1280×844 화면을 확인했다. 벽 배치가 막힌 오류 안내는 방 아래에 표시해 드래그 중 방의 위치를 흔들지 않는다. 빠른 터치 종료는 합쳐진 마지막 move 이벤트 대신 release의 최종 손 위치까지 반영한다. 운영 API 쓰기/Mock 운영 호출은 없었다.

미리보기는 `http://localhost:8082/room-edit`다. 기기나 로그인 없이 Mock에서 확인할 수 있다. 화면 확인 후 실제 API에서는 최신 응답 지원 여부와 운영 계정 상태를 별도로 확인한다.

## 외부 조건이 남은 항목

- 벽 배치: 백엔드 최신 코드는 지원하지만 기존 DB 반영/운영 배포를 확인해야 한다. 실제 응답이 새 계약일 때만 벽 드래그를 제공한다. solid 겹침 제한은 최초 명세와 차이가 있어 팀 확인이 필요하다.
- 운영진의 타인 파트 변경: 현재 API는 `partId` 변경을 본인에게만 허용한다. 내 파트 변경은 구현했지만 타인 변경은 계약 조율 전까지 구현 완료로 보지 않는다.
- Google/Kakao: 공급자·모바일 callback의 백엔드 준비 이후 연결해야 한다. 이메일 인증/재설정의 실제 메일 수신과 모바일 복귀도 운영 계정/기기 검증이 필요하다.
- 푸시: 알림 수신 설정·읽음/배지는 구현했다. Firebase·기기 토큰·실제 발송/수신은 별도 네이티브 빌드 단계다.
- 앱 차단: 안내·세션 복귀만 구현했다. 실제 선택/권한/차단/해제는 Android/iOS별 구현과 실기기 검증이 필요하다. iOS 기기 빌드의 유료 멤버십·테스트 기기·Bundle ID는 미확정이다.
- 최종 표현·출시: 팀 에셋/폰트 제공, 실제 계정·접근성·키보드/뒤로가기·여러 기기·배포 빌드 검증이 남아 있다.

이 항목을 제외한 공통 화면과 계약에 맞는 API 흐름은 1차 구현을 연결한 상태다. 외부 조건이 남은 기능을 가짜 성공이나 임시 토글로 완료 처리하지 않는다.
