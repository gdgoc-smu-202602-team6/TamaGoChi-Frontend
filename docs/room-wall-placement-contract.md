# 시계·창문 드래그: 저장 계약 제안

상태: 사용자 요청에 따른 제안. 현재 운영 API의 지원 완료를 의미하지 않는다.

## 확인된 제약

2026-11-03(KST)에 Backend origin/main `98441b9ec93e1089f6419476286bc4ef812b6e44`를 다시 확인했다.

- OpenAPI의 `PlacementTarget`은 DESK·BOOKSHELF·PLANT·RUG·CHARACTER만 허용한다.
- `slot-of.ts`에서 CLOCK·WINDOW·LAMP는 배치 대상이 없는 일반 슬롯이다.
- `Room.withPlacements`는 배치 대상이 아닌 요청을 거부한다. 기존 placements에 CLOCK·WINDOW를 임의로 넣어도 저장되지 않는다.
- RoomUpdate는 additionalProperties를 허용하지 않으므로 새로운 필드를 프론트엔드에서 보내는 것만으로 지원할 수 없다.

## 제안하는 확장

기존 바닥 배치는 유지하고 벽 전용 `wallPlacements`를 추가한다. 아래 형식은 합의·구현이 필요한 제안이다.

```json
{
  "wallPlacements": [
    { "target": "WINDOW", "wall": "LEFT", "u": 0.65, "v": 0.45 },
    { "target": "CLOCK", "wall": "RIGHT", "u": 0.35, "v": 0.3 }
  ]
}
```

| 필드 | 제안 의미 |
| --- | --- |
| target | CLOCK 또는 WINDOW. 같은 대상은 한 번만 배치 |
| wall | LEFT 또는 RIGHT |
| u | 벽의 뒤쪽 모서리에서 바깥쪽 모서리까지 0~1 |
| v | 벽 위쪽에서 바닥선까지 0~1 |

화면 픽셀이나 기기 해상도를 저장하지 않는다. 그림 크기에 따른 벽 안쪽 보정은 렌더러에서 처리한다. 방 크기를 바꿔도 정규화된 벽 위치를 유지할 수 있다. 실제 에셋별 중심·크기는 교체 가능한 메타데이터로 분리한다.

## 서버에서 정할 사항

- Room 응답과 RoomUpdate에 해당 필드를 추가하고 OpenAPI·검증·저장소·e2e를 함께 갱신한다.
- 장착 중인 시계·창문만 배치하며 다른 사용자 방 쓰기는 기존처럼 금지한다.
- PATCH에서 필드 생략은 기존 벽 배치 유지, 빈 배열은 벽 기본 위치로 초기화한다.
- 해당 슬롯을 해제하면 벽 배치를 제거하고, 같은 슬롯 교체 시에는 위치를 유지한다.
- 바닥 장착·배치와 벽 배치를 완료 시 한 번에 저장한다. 사용자 상태·보상·방명록 읽음은 변경하지 않는다.
- 기존 배치가 없는 사용자는 기본 위치로 표시한다. 배포된 API가 지원하는지 식별할 응답 계약도 함께 정한다.

## 구현 범위 선택

백엔드 확장과 함께 구현하면 기기 간 위치를 공유할 수 있다. 현재 기기에만 저장하는 방식은 계정별 로컬 설정과 저장 실패·로그아웃·캐시 초기화 정책이 별도로 필요하다. 미리보기만 구현한다면 Mock 전용임을 분명히 하고 실제 API 저장 성공으로 표시하지 않아야 한다.

저장 방식을 결정하기 전에는 기존 API에 지원되지 않는 target·필드를 추가하거나, 저장되지 않은 벽 위치를 저장 완료로 안내하지 않는다.
