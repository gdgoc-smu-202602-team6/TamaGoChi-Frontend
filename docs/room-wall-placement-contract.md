# 바닥·벽 배치 계약과 드래그

2026-11-04(KST), Backend `origin/main` [`01ace7c`](https://github.com/gdgoc-smu-202602-team6/TamaGoChi-Backend/commit/01ace7cb3d1d9ae3f84d52c929b3f2d824715ff2)의 OpenAPI·배치 도메인·카탈로그 seed를 확인해 공통 프론트엔드에 연결했다. 아래 초기 `wallPlacements` 제안은 채택되지 않았다. 현재는 서버가 정한 `placements[].surface`와 아이템별 `placementPolicy`를 사용한다.

이 확인은 운영 DB/API에 이미 반영됐다는 의미가 아니다. 해당 커밋은 버전 0.2.0의 릴리스 파일을 되돌렸으며 기존 DB의 배치 스키마 반영 방식은 백엔드에서 정해야 한다. 프론트엔드는 실제 Room 응답의 `wallHeight: 3`과 카탈로그 정책을 읽어 새 배치를 사용한다. 이전 응답에서는 기존 바닥 배치와 고정 시계·창문을 유지하고 지원하지 않는 벽 쓰기를 보내지 않는다.

## 현재 저장 형식

새 계약의 꾸미기 PATCH는 `{ equipped: [{ slot, itemId }], placements: [{ target, surface, x, y }] }`다. `wallHeight`는 읽기 전용으로 내부 모델에 보관하며 PATCH에 넣지 않는다. 상태·좋아요·방명록 확인 시각도 보내지 않는다.

| 값 | 계약 |
| --- | --- |
| `surface` | `FLOOR`, `LEFT_WALL`, `RIGHT_WALL` |
| 원점·단위 | 두 벽이 만나는 바닥 모서리, 칸 단위 |
| 바닥 축 | x는 오른쪽 벽 방향, y는 왼쪽 벽 방향 |
| 벽 축 | x는 벽을 따라 바깥쪽, y는 바닥에서 위쪽 |
| `x`, `y` | 대상 사각형에서 원점에 가장 가까운 꼭짓점 |
| `placementPolicy` | 아이템의 면 종류·가로/세로 크기·선택적 이동 간격·solid 여부 |
| 캐릭터 | 바닥 1×1, 자유 이동, solid. 백엔드와 같은 고정 규칙 |

배치할 수 있는 아이템은 장착 아이템의 정책에서 찾는다. 현재 seed는 시계·창문을 벽에, 책상·책장·화분·러그를 바닥에 배치한다. 스탠드와 캐릭터 장식에는 배치 정책이 없다.

새 API는 같은 면의 solid 사각형 겹침을 거부하며 경계가 닿는 것은 허용한다. 서로 다른 면과 non-solid 러그는 겹칠 수 있다. 이는 최초 제공 명세의 포괄적인 겹침 허용과 다른 백엔드 제한이므로 팀의 규칙 확인 항목으로 남긴다. 프론트엔드는 새 계약에 있는 정책만 적용하며 이전 API에는 이 제한을 추가하지 않는다.

## 사용자 동작과 공통 표현

시계·창문을 직접 터치하거나 마우스로 끌며, 방 모서리를 넘어 반대 벽으로 옮길 수 있다. 면 크기에서 아이템 폭·높이를 뺀 범위와 정책의 이동 간격에 맞춘다. 벽 물건은 벽 기울기에 맞춰 그리며 썸네일의 빈 여백과 바닥 그림자를 붙이지 않는다. 위치·정책 숫자는 제품 화면에 노출하지 않는다.

완료 전에는 저장하지 않는다. 완료 시 한 번에 저장하고 Home·Study·결과·친구 방은 같은 렌더러로 표시한다. 위치 초기화는 배치만 비우며 장착·계약 정보를 유지한다. 방 확장 때 벽 x와 바닥 x/y는 크기 비율로 조정하고 벽 y는 유지한다. 정책에 맞지 않거나 충돌하는 저장 위치는 서버와 같은 대상 이름 순서로 기본 위치로 돌린다. 슬롯 해제는 그 슬롯의 배치도 제거한다.

서버 변경·소유권 상실·새/이전 계약 전환을 확인하면 초안을 무조건 덮어쓰지 않는다. 저장 응답이 유실되면 GET으로만 확인하고 PATCH를 자동 반복하지 않는다.

## Mock과 검증

앱의 Mock 미리보기는 새 면 배치다. 기존 공부 저장소의 배치는 읽을 때만 새 크기 기준으로 변환하며 읽기 자체로 저장하지 않는다. 명시적 꾸미기 저장/구매 시 `roomPlacementVersion: 2`와 새 배치를 같은 저장소에 저장한다. 공부·보상·목표·현재 세션은 유지하고 손상된 이전 기록을 변환으로 숨기거나 삭제하지 않는다. 기존 바닥 계약의 회귀 테스트도 유지한다.

타입·린트·총 388개 테스트와 API Android/iOS/Web·Mock Web 번들을 통과했다. 새/이전 DTO·정책·면/크기/간격·충돌/접촉·벽 전환·좌표 변환·확장/해제/초기화·동시 변경·보내는 필드·Mock 이관/영속성/공부 보존을 확인했다. 브라우저의 드래그·저장·재진입·응답 유실/계정 격리와 전체 공통 기능의 남은 조건은 [공통 기능 점검](common-features-checklist.md)에 기록한다.

## 확인된 제약

2026-11-03(KST)에 Backend origin/main `98441b9ec93e1089f6419476286bc4ef812b6e44`를 다시 확인했다.

- OpenAPI의 `PlacementTarget`은 DESK·BOOKSHELF·PLANT·RUG·CHARACTER만 허용한다.
- `slot-of.ts`에서 CLOCK·WINDOW·LAMP는 배치 대상이 없는 일반 슬롯이다.
- `Room.withPlacements`는 배치 대상이 아닌 요청을 거부한다. 기존 placements에 CLOCK·WINDOW를 임의로 넣어도 저장되지 않는다.
- RoomUpdate는 additionalProperties를 허용하지 않으므로 새로운 필드를 프론트엔드에서 보내는 것만으로 지원할 수 없다.

## 제안하는 확장

기존 바닥 배치는 유지하고 벽 전용 `wallPlacements`를 추가한다. 아래 형식은 합의·구현이 필요한 제안이다.

```json
{
  "wallPlacements": [
    { "target": "WINDOW", "wall": "LEFT", "u": 0.65, "v": 0.45 },
    { "target": "CLOCK", "wall": "RIGHT", "u": 0.35, "v": 0.3 }
  ]
}
```

| 필드 | 제안 의미 |
| --- | --- |
| target | CLOCK 또는 WINDOW. 같은 대상은 한 번만 배치 |
| wall | LEFT 또는 RIGHT |
| u | 벽의 뒤쪽 모서리에서 바깥쪽 모서리까지 0~1 |
| v | 벽 위쪽에서 바닥선까지 0~1 |

화면 픽셀이나 기기 해상도를 저장하지 않는다. 그림 크기에 따른 벽 안쪽 보정은 렌더러에서 처리한다. 방 크기를 바꿔도 정규화된 벽 위치를 유지할 수 있다. 실제 에셋별 중심·크기는 교체 가능한 메타데이터로 분리한다.

## 서버에서 정할 사항

- Room 응답과 RoomUpdate에 해당 필드를 추가하고 OpenAPI·검증·저장소·e2e를 함께 갱신한다.
- 장착 중인 시계·창문만 배치하며 다른 사용자 방 쓰기는 기존처럼 금지한다.
- PATCH에서 필드 생략은 기존 벽 배치 유지, 빈 배열은 벽 기본 위치로 초기화한다.
- 해당 슬롯을 해제하면 벽 배치를 제거하고, 같은 슬롯 교체 시에는 위치를 유지한다.
- 바닥 장착·배치와 벽 배치를 완료 시 한 번에 저장한다. 사용자 상태·보상·방명록 읽음은 변경하지 않는다.
- 기존 배치가 없는 사용자는 기본 위치로 표시한다. 배포된 API가 지원하는지 식별할 응답 계약도 함께 정한다.

## 구현 범위 선택

백엔드 확장과 함께 구현하면 기기 간 위치를 공유할 수 있다. 현재 기기에만 저장하는 방식은 계정별 로컬 설정과 저장 실패·로그아웃·캐시 초기화 정책이 별도로 필요하다. 미리보기만 구현한다면 Mock 전용임을 분명히 하고 실제 API 저장 성공으로 표시하지 않아야 한다.

저장 방식을 결정하기 전에는 기존 API에 지원되지 않는 target·필드를 추가하거나, 저장되지 않은 벽 위치를 저장 완료로 안내하지 않는다.
