# 상점 구현과 검증

## 화면과 디자인

Claude Design 이미지와 기획 v4의 `19-shop` 화면을 기준으로 하늘색 배경, 게임 로고·Bolt 헤더, 큰 SHOP 제목, 네 카테고리, 두 열 카드, 큰 미리보기, 등급·레벨 배지, 노란 구매 버튼을 구현했다. 보유/장착은 녹색 버튼으로 구분한다. 가격·레벨·등급은 시안의 예시 숫자가 아닌 서버 카탈로그를 사용한다.

`src/app/(tabs)/shop.tsx`는 기능 화면만 내보내고 구현은 `src/features/shop/`에 둔다. 단일 FlatList로 스크롤하며 마지막 홀수 카드도 반쪽 폭을 유지한다. 공통 `GameHeader`를 내 방·상점에서 사용하며 버튼의 보유 상태 색상과 접근성 이름을 확장했다. 탭 내비게이션·패키지 의존성·네이티브 프로젝트는 변경하지 않았다.

미리보기는 임시 SVG다. `components/item-preview.tsx`의 레지스트리에 서버 `Item.code`별 최종 에셋을 등록할 수 있다. 아직 등록하지 않은 코드는 슬롯별 그림으로 표시한다. 서버 장착 상태는 상점 배지에 반영하지만, Home 방 그림의 실제 장착 아이템·배치 좌표 렌더링은 꾸미기 단계에 남아 있다.

## API 계약

Backend `98441b9`의 OpenAPI 0.1.0과 게임 API 컨트롤러, 시드 카탈로그를 확인했다. 기본 API 모드는 계정별 고정 Bearer 토큰을 쓰며 실패 시 Mock으로 대체하지 않는다.

| 요청 | 사용 정보 |
| --- | --- |
| `GET /items` | 전체 카탈로그. 네 카테고리 필터는 받은 목록에서 적용 |
| `GET /users/me/items` | 기본 보유를 포함한 아이템 ID |
| `GET /users/me/room` | 슬롯별 장착 ID |
| `GET /users/me/stats` | 현재 Bolt·레벨 |
| `PUT /users/me/items/{itemId}` | 새 구매·자동 장착. 요청 본문 없이 ID만 전송 |

새 구매는 201, 이미 보유한 아이템은 차감이나 재장착 없이 200이다. 화면에서는 보유/장착 버튼을 비활성화한다. 레벨 제한 해제 후에도 카탈로그 가격으로 구매해야 한다. 구매 확인 팝업·보유 아이템 재장착 기능은 추가하지 않았다.

`409 level-locked`의 `requiredLevel`, `409 insufficient-volts`의 `shortBy`, 404를 구분해 안내한다. 공통 HTTP 오류는 두 숫자 필드만 안전한 정수로 보관하고 응답 원문·인증 정보는 오류 메시지에 넣지 않는다. 카탈로그·보유 영수증·장착 슬롯과 숫자 응답을 런타임 검증한다.

## 구매와 복구

- 중복 탭과 다른 카드의 동시 구매를 막는다. 클라이언트에서 잔액 차감이나 보유 추가를 먼저 적용하지 않는다.
- PUT 완료/실패 후 네 리소스를 다시 조회한다. 응답 유실 후에도 실제 보유를 확인하면 그 상태를 표시한다.
- 재조회 실패 시 이전 데이터를 유지하고 구매를 잠근다. 사용자가 다시 불러오기로 실제 잔액과 보유를 확인한 뒤 구매할 수 있다. 재조회 버튼은 PUT을 재전송하지 않는다.
- 구매 이전에 시작한 오래된 GET은 새 상태를 덮어쓰지 않는다. 구매 이후 Home도 다시 조회하며, 상점 탭에 돌아올 때도 갱신한다.
- 계정 변경은 Provider·화면 상태를 새로 만들고 이전 계정의 늦은 응답을 버린다. 여러 기기의 동시 구매와 차감 원자성은 서버 계약에 의존한다.

Mock 모드는 기존 `@tamagochi/mock-study/v1` 레코드에 선택적 상점 필드를 추가한다. 이전 공부 기록·활성 세션·보상은 초기화하지 않는다. 구매와 공부 종료를 같은 큐에서 처리하고 하나의 저장 작업으로 잔액·보유·장착을 보존한다. 같은 슬롯은 교체하고 다른 슬롯은 유지한다. 이후 마이 작업에서 확인한 서버 레벨 곡선을 Mock에 적용해, 공부 종료 XP가 Home·Profile·상점 해금에 같은 레벨로 반영된다. 실제 API 모드는 서버 Stats만 사용한다.

## 검증과 남은 범위

`npm run typecheck`, `npm run lint -- --no-cache`, `npm test`로 확인한다. 총 59개 테스트에 상점 관련 12개를 추가했다. 카탈로그 검증, 구매 요청·영수증, 409 상세 정보, 상태 우선순위, 중복 구매, 같은 슬롯 교체, 공부 보상과 구매의 공유 잔액, 저장 실패·기존 레코드 보존을 검증한다.

Android·iOS·Web 번들 내보내기로 크로스 플랫폼 컴파일을 확인한다. 실제 인증 계정의 운영 구매·서버 동시 차감, 실기기 조작과 최종 에셋은 별도 검증이 필요하다. 기존 Metro 개발 SSR의 `unknown module` 문제는 남아 있어 Web 미리보기는 프로덕션 내보내기와 `expo serve`를 사용한다.

격리된 Chrome 프로필에 API 계약 테스트 응답을 주입해 로그인 진입 제한, 네 카테고리, 중복 클릭, 구매 후 Home 잔액 갱신, 구매 응답 유실, 재조회 실패 후 구매 잠금·재시도, 같은 슬롯 교체, 서버의 레벨·Bolt 충돌, 빈 목록·로드 오류, 계정 변경을 검증했다. 320·390·1280px의 카드 배치와 가로 넘침, 미등록 에셋 코드의 대체 그림을 확인했다. 운영 계정이나 실제 구매 요청은 만들지 않았다.

Mock 브라우저에서도 구매 → 새로고침 → 공부 종료 보상 → 추가 구매를 확인했다. 잔액이 `155 → 95 → 96 → 56`으로 이어지고, 기존 공부 결과와 보유 내역이 함께 보존되며 API 호출은 없었다.

## 로컬 미리보기

PowerShell에서 Mock 화면을 열려면 다음을 실행한다. 실행 중인 미리보기를 새 코드로 바꾸려면 서버를 종료하고 다시 내보낸 뒤 실행한다.

```powershell
$env:EXPO_PUBLIC_DATA_MODE='mock'
npx.cmd expo export --platform web --output-dir .expo/preview
npx.cmd expo serve .expo/preview --port 8082
```

같은 PC의 브라우저에서 `http://localhost:8082/shop`으로 접속한다. 로그인 없이 둘러보고 구매할 수 있다. 공부로 모은 Bolt와 구매 내역은 해당 브라우저에 저장된다. API 모드를 확인하려면 환경 변수를 `api`로 바꿔 새로 내보내고 실행한 뒤 실제 인증 계정으로 로그인한다.
