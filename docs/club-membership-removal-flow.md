# 부원 강퇴·동아리 탈퇴

## 화면과 권한

2026-11-04(KST)에 Backend `98441b9`의 Members 컨트롤러·repository·e2e와 Prisma 관계, 제공된 OpenAPI 0.1.0을 확인했다. 기존 동아리 관리의 하늘색 배경·크림색 카드·네이비 테두리·노란 버튼과 공통 `GameConfirmDialog`를 재사용한다. 새 에셋·패키지는 추가하지 않았다.

`부원·역할 관리`에서 다른 부원의 `강퇴`를 누르면 닉네임과 삭제 범위를 확인한다. 정확한 `members.manage` 권한이 필요하며 본인은 이 버튼에 표시하지 않는다. 내 탈퇴는 별도 `/clubs/{clubId}/leave` 화면에서 현재 동아리·닉네임·가입일을 확인한 뒤 실행한다. 공지·마이의 선택된 동아리, 가입 목록의 각 동아리, 부원 관리 화면에서 진입하며 일반 부원도 이용할 수 있다. 모두 인증이 필요한 루트 Stack 화면이다.

삭제되는 것은 해당 동아리의 부원 자격과 공지 읽음이다. 개인 공부 기록·볼트·경험치·방은 유지한다. 계정 탈퇴와 구분하며 재가입에는 새 신청과 승인이 필요하다. 마지막 `members.manage` 보유자는 강퇴·탈퇴할 수 없으며 409 `last-manager`에 다른 부원에게 관리 권한을 먼저 부여하도록 안내한다.

## API와 대상 확인

| 요청 | 용도 |
| --- | --- |
| `GET /clubs/-/members?userId=me&pageSize=200` | 내 부원 자격을 모든 페이지에서 확인 |
| `GET /clubs/{clubId}` | 현재 동아리 이름과 부원 수 |
| 부원 관리의 권한·역할·전체 목록 조회 | 강퇴 권한과 대상의 최신 자격 확인 |
| `DELETE /clubs/{clubId}/members/{memberId}` | 확인한 부원 자격 하나 제거, 본문 없음 |

본인 탈퇴도 `me` 대신 확인한 구체적인 부원 UUID를 DELETE한다. 이전 요청이 지연되거나 결과 확인 전에 재가입해도 새 자격을 지우지 않기 위해서다. 내 목록은 현재 로그인 사용자 ID와 일치하는지 검사하고, 반복 페이지 토큰·중복 동아리/부원·잘못된 DTO를 거절한다. 내 목록에서 자격이 없으면 동아리의 비공개 정보는 요청하지 않는다. 동아리 GET의 404만으로 탈퇴를 확정하지 않고 내 전체 목록을 다시 확인한다.

확인창을 열 때의 대상 원본을 유지한다. 실행 직전에 ID·동아리·사용자·가입일·닉네임·파트·역할을 다시 비교하고 바뀌었으면 DELETE 없이 재선택을 요구한다. 대상이 이미 없으면 추가 DELETE 없이 현재 상태를 보여준다. 사전 확인 이후의 동시 변경을 막는 ETag·조건부 삭제 계약은 없으므로 최종 권한과 마지막 관리자 제약은 서버가 판정한다.

## 응답 유실·선택 정리

화면과 서비스가 중복 실행을 막는다. 확정된 4xx는 반복하지 않는다. 404·네트워크·타임아웃·5xx 또는 삭제 후 결과 조회 실패는 GET으로 확인하고 DELETE를 자동 재전송하지 않는다. 결과를 읽지 못했거나 동일 자격이 남아 있으면 변경 버튼을 잠근다. `부원 목록 다시 확인`과 `부원 자격 다시 확인`은 조회만 하며, 확인 후 사용자가 작업을 새로 선택한다.

강퇴 결과는 “현재 목록에 대상 부원이 없음을 확인했어요”로 표시하며 누가 제거했는지 추정하지 않는다. 탈퇴 결과 조회에서 다른 부원 ID가 나오면 새 자격은 보존하고 안내한다. 권한 회수·인증 만료에서는 이전 관리 내용을 내린다. 처리 중 앱 내부 이동 버튼을 비활성화하고 Stack 제거를 막는다. 브라우저 전체 페이지 이동·새로고침을 차단하는 기능은 아니며 재진입 시에는 조회부터 수행한다.

자격이 없음을 확인하면 `ClubProvider.forgetClub`이 메모리에서 해당 동아리를 즉시 제외하고 남은 선택 또는 빈 선택으로 전환한다. 그 전에 시작한 목록/선택 응답은 세대 번호로 폐기한다. 진행 중이던 저장/조회를 기다린 뒤 현재 목록과 저장 선택을 정리한다. 선택 저장에 실패해도 탈퇴한 동아리를 메모리에 복원하지 않으며 조회 오류와 재확인을 표시한다. API 모드에서는 삭제 초안이나 미확정 요청을 저장하지 않는다.

## Mock 일관성

`@tamagochi/mock-member-removals/v1`에 `{ version: 1, members: [{ id, clubId, userId, joinedAt }] }`만 저장한다. 이 정확한 자격에 대한 제거 기록을 실제 목록·권한·부원 수·초대 코드 검색·파트 사용 검사에 함께 적용한다. 역할 변경과 제거는 같은 저장소의 공유 잠금을 사용해 동시에 마지막 관리자 둘이 사라지는 상황을 막는다. 손상·저장 실패 시 원본이나 다른 기록을 지우지 않는다.

제거된 기본 자격은 재실행해도 돌아오지 않는다. 새 승인에는 신청별 새 부원 ID와 일반 역할을 부여하므로 예전 운영진 override가 이어지지 않는다. 새 동아리도 탈퇴 후 다시 신청할 수 있다. 승인된 예전 신청은 실제 자격을 대신하지 않으며 파트 삭제 제한에는 현재 부원과 대기 신청만 사용한다.

기존 기본 자격의 읽음은 호환 키 `@tamagochi/mock-notice-reads/v1`을 유지한다. 신규 승인·재가입 자격은 `@tamagochi/mock-notice-reads/v2/{clubId}/{memberId}`로 분리하고 모든 공지를 읽지 않은 상태로 시작한다. 예전 읽음 기록은 보존하되 새 자격에 적용하지 않는다. 개인 공부/상점/방 저장소는 수정하지 않는다.

## 검증과 미리보기

타입·린트, 총 282개 테스트와 API Android/iOS/Web·Mock Web 번들 생성이 통과했다. 새 18개 테스트는 본인/타인 권한, 전체 페이지·계정/DTO 검증, 정확한 본문 없는 DELETE, 원본 변경·중복·마지막 관리자, 응답 유실과 미적용·재가입 자격 보존, Mock 제거 유지·공유 잠금·저장 실패·재가입 권한/읽음·개인 기록 보존을 검증한다.

격리 Chrome에서 가짜 API로 인증 제한·강퇴 취소/중복·열린 확인창의 외부 변경·마지막 관리자·응답 유실·조회 실패 후 수동 복구·재가입 자격 보존을 확인했다. 탈퇴 중 이전 목록 응답이 늦게 도착하고 선택 저장도 실패하는 경우, 다음 동아리 선택·빈 소속·계정 전환·만료도 확인했다. API와 Mock 모두 320×568·390×844·1280×844에서 가로 넘침과 확인창 버튼 접근을 확인했다.

Mock 브라우저에서는 일반 부원 탈퇴 유지·접근 차단·대기 후 승인된 재가입·일반 역할/읽음 초기화·강퇴와 실제 인원 수·저장 실패/명시적 재선택·관리자 인계 후 탈퇴·소속 없음·마이 진입·새 생성자 보호·공부 결과 보존을 확인했다. 공유 데이터 변경 후 기존 역할 관리와 초대 코드 가입·취소·승인 브라우저 검증도 통과했다. 운영 API 네트워크를 차단했으며 운영 데이터를 변경하지 않았다. 실제 계정·Android/iOS 뒤로가기·화면 읽기·다중 기기 동시 검증은 남아 있다.

`http://localhost:8082/notice`에서 `동아리 탈퇴`, 첫 동아리의 `부원·역할 관리`에서 `강퇴`를 확인한다. 일반 부원 탈퇴를 바로 보려면 `/clubs/mock-club-pixel/leave`를 연다. 마지막 관리자 제한은 `/clubs/mock-club-study/leave`에서 확인할 수 있다. 현재 브라우저에 남은 Mock 상태에 따라 소속·권한이 달라질 수 있다.
