# 초대 코드 가입 신청과 상태 확인

## 화면과 범위

기획 v4의 `04-club-join`·`05-club-pending`과 사용자 기능 명세를 참고했다. 하늘색 배경, 크림색 코드 입력 카드, 동아리 정보·부원 수·동적 파트 선택 카드, 노란 버튼과 모래시계 대기 표시를 사용한다. 긴 한글 안내는 시스템 폰트로 표시하고 기존 게임 컴포넌트를 재사용했다.

`/clubs/join`은 인증이 필요한 루트 Stack 화면이며 하단 탭을 표시하지 않는다. 공지의 미가입 안내·목록 하단, 마이에서 열 수 있다. 코드를 조회하고 파트를 고르면 신청을 보낼 수 있으며, 내 신청 내역의 대기·승인·거절과 취소를 확인한다. 내 방으로 돌아가는 것은 신청을 취소하지 않는다.

권한 관리·동아리 탈퇴는 이번 범위에 포함하지 않았다. 후속 작업에서 [운영진의 승인·거절](club-applications-flow.md)을 추가했으며 권한이 있는 동아리 카드에 관리 버튼을 표시한다. 동아리 생성도 구현했으며 이 화면의 `새 동아리 만들기`에서 연다([생성 흐름](club-create-flow.md)). 시안의 `(데모) 승인됨 → 시작하기`는 추가하지 않았다. 가입 대기 중에도 개인 공부·내 방·상점·마이를 사용할 수 있다.

## API 계약

Backend `98441b9`의 OpenAPI 0.1.0, Clubs·Applications 컨트롤러와 현재 부원 목록 계약을 확인했다. `ClubJoinService`는 계정별 고정 Bearer 토큰 클라이언트와 기존 Notice 서비스의 부원 자격 조회를 사용한다.

| 요청 | 용도 |
| --- | --- |
| `GET /clubs?inviteCode=XXXXXXXX` | 초대 코드에 해당하는 동아리 미리보기. 없으면 빈 목록 |
| `GET /clubs/{clubId}/parts` | 로그인한 신청자에게 허용된 현재 파트 목록 |
| `GET /clubs/-/applications?userId=me&pageSize=200` | 내 신청들. 마지막 페이지까지 조회 |
| `POST /clubs/{clubId}/applications` | 본문은 `{ partId }`만 전송 |
| `GET /clubs/{clubId}/applications/{applicationId}` | 취소 직전 신청 상태 확인 |
| `DELETE /clubs/{clubId}/applications/{applicationId}` | 본인의 PENDING 신청만 취소 |
| 기존 `/clubs/-/members?userId=me`·동아리 조회 | 현재 가입된 동아리를 확인하고 공지 진입에 사용 |

초대 코드는 양끝 공백 제거·대문자 변환 후 영문 대문자/숫자 8자리를 검사한다. 하이픈이나 내부 공백은 허용하지 않는다. 동아리·파트·신청 ID, 색상·상태·날짜·페이지 토큰과 신청자 ID를 검증한다. 다른 사용자의 신청 응답은 거부하고, 닉네임·이메일 등 필요 없는 응답 필드는 화면 모델에 보관하지 않는다.

## 신청·취소·재조회

- 신청 전에 내 대기 신청과 현재 파트를 다시 조회한다. 기존 대기가 있으면 그 신청을 사용하며 파트를 바꾸거나 POST를 반복하지 않는다. 파트가 없어졌으면 다시 동아리를 찾도록 안내한다.
- 신청 성공을 로컬에서 먼저 만들지 않는다. POST 후 목록을 다시 읽고 대기 신청 또는 실제 부원 자격을 확인한다. `already-member`·`application-pending`도 같은 재조회로 실제 상태를 반영한다.
- 중복 탭을 막는다. 응답 유실 후 재조회에서 대기를 확인하면 추가 신청 없이 복구한다. 재조회까지 실패하면 쓰기를 막고 상태 다시 확인을 안내한다. 이 버튼은 조회만 하며 POST/DELETE를 재전송하지 않는다.
- 취소 전에 정확한 신청을 GET한다. 이미 승인·거절되었으면 DELETE하지 않는다. GET 뒤에 상태가 바뀐 `not-pending`도 다시 조회해 반영한다. 부원 자격을 삭제하는 API를 호출하지 않는다.
- 취소 응답이 유실됐거나 이미 신청이 없어졌으면 대기 내역이 없음을 표시한다. 승인된 신청이 남아 있으면 취소 완료라고 표시하지 않는다.
- 화면 진입·foreground 복귀·명시적 새로고침, 대기 신청이 있는 동안 30초 간격으로 상태를 조회한다. 앱 push 알림을 받은 것처럼 표시하지 않는다.
- 승인 기록만으로 공지를 열지 않는다. 현재 부원 목록에 있는 동아리만 열 수 있으며, 열기 직전에 공통 ClubProvider를 갱신하고 선택 저장 성공까지 확인한다. 저장 실패나 자격 변경 시 이전 동아리로 잘못 이동하지 않는다.

이를 위해 ClubProvider의 동시 목록 조회는 같은 Promise를 기다리도록 조정했고, 선택 결과를 boolean으로 반환하도록 했다. 기존 공지의 동아리 선택·읽음·페이지 흐름도 브라우저에서 다시 확인했다. 계정 변경은 기존 게임 scope·편집 상태·지연 응답을 폐기한다.

## 동아리 이름 캐시

신청 목록의 계약에는 `clubId`만 있고 동아리 이름이 없다. 가입 전에는 `GET /clubs/{clubId}`도 부원 권한이 필요하므로, 초대 코드 조회로 확인한 동아리 이름·파트 라벨만 계정별로 보관한다. 키는 `@tamagochi/club-names/v1/{API 주소}/{사용자 ID}`이며 초대 코드·토큰·신청자 이메일을 저장하지 않는다.

이 캐시는 표시용이다. 신청 상태나 부원 자격을 결정하지 않는다. 가입된 동아리는 현재 조회한 이름을 우선한다. 캐시가 없거나 읽기에 실패하면 일반 신청 이름·파트 정보 없음으로 표시하며 서버 조회를 계속한다. 삭제된 파트의 `partId: null`은 구분해 표시한다. 캐시의 이름은 마지막 초대 코드 조회 시점의 정보이며, 서버가 신청 목록에 동아리 이름을 제공하는 계약은 추가하지 않았다.

## Mock

`MORI2026`으로 “함께 성장하는 숲”과 두 파트를 조회할 수 있다. 기존의 기본 가입 동아리 두 개는 유지한다. 신청은 별도 `@tamagochi/mock-club-applications/v1`에 직렬 저장하며 기존 공부·목표·상점·공지 읽음 데이터를 변경하거나 초기화하지 않는다. 대기 신청의 중복 생성, 저장 실패·손상 보존, 취소와 거절 이력을 처리한다. 거절 후 7일이 지난 항목은 표시에서 제외하지만 저장 데이터를 삭제하지 않는다.

Mock 가입 상태와 공지의 부원 목록은 `mocks/clubs.ts`의 같은 자료를 사용한다. 대기는 공지 접근을 허용하지 않는다. 내 신청을 자동 승인하거나 본인에게 승인 버튼을 제공하지 않는다. 가입 흐름 검증에서는 저장소에 승인된 결과를 주입해 이후 공지 진입을 확인했다. 별도의 운영진 화면은 첫 동아리의 외부 신청자를 처리하며, 내 `MORI2026` 신청과 구분한다([신청 관리](club-applications-flow.md)).

```powershell
npm.cmd run typecheck

```

총 100개 테스트가 통과했다. 이번 작업의 15개는 코드·미리보기·현재 파트·본인 신청 페이지, 요청 본문과 중복 처리, 응답 유실·승인/취소 경합, 잘못된 응답, 표시 캐시와 Mock 저장·접근 제어를 검증한다. Mock 공지 테스트의 저장소도 실제처럼 키별 데이터를 구분하도록 갱신했다.

격리된 Chrome에 API 응답을 주입해 인증 전 차단, 공지에서 진입, 탭 숨김, 코드·파트 선택, 신청 직전 파트 삭제, 중복 클릭, 새로고침, 개인 공부 진입, 신청/취소 응답 유실, 결과 재조회 실패, 취소 직전 승인, 선택 저장 실패, 실제 부원 확인 후 공지 진입, 409·거절·삭제된 파트, 계정별 이름·신청 격리와 만료를 확인했다. 320·390·1280px의 배치도 확인했다. 운영 계정이나 실제 신청은 변경하지 않았다.

Mock에서는 대기·재실행·개인 공부 종료·취소 저장 실패와 재신청, 승인 결과 주입 후 공지 진입·선택 복원과 기존 공부 기록 보존을 확인했다. Android·iOS·Web 내보내기도 통과했다. 실제 인증 계정과 운영진 계정의 승인/취소 동시 처리, 모바일 키보드·화면 읽기·실기기 복귀 검증은 남아 있다. 기존 Metro 개발 SSR 오류는 별도이며 내보낸 Web 빌드로 검증했다.

새 라우트 추가 후 IDE의 경로 타입이 오래되었으면 공식 `npx.cmd expo customize tsconfig.json`으로 생성 타입을 갱신한다. 생성된 라우트 타입을 직접 수정하거나 경로 타입 단언으로 우회하지 않았다.

## 미리보기

```powershell
$env:EXPO_PUBLIC_DATA_MODE='mock'
npx.cmd expo export --platform web --output-dir .expo/preview
npx.cmd expo serve .expo/preview --port 8082
```

같은 PC에서 `http://localhost:8082/clubs/join`을 열고 `MORI2026`을 입력한다. 실제 API 모드는 `EXPO_PUBLIC_DATA_MODE=api`로 다시 내보내고 로그인한다. 실제 초대 코드와 운영진의 승인 처리가 필요하다.
