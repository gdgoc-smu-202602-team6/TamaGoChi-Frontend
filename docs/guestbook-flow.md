# 방명록

## 화면과 범위

2026-11-04(KST)에 Backend `98441b9`의 MyGuestbookEntries·GuestbookEntries 컨트롤러, GuestbookEntryRepository·GuestbookText·Room의 확인 시각과 OpenAPI 0.1.0을 확인했다. 기획 v4의 내 방명록·친구 방 아래 방명록에서 크림색 패널·네이비 테두리·노란 작성 버튼, 작성자·날짜·NEW·답방 배치를 참고한다. 긴 한글은 기존 시스템 폰트로 표시하며 새 패키지나 에셋은 추가하지 않았다.

내 방의 `방명록`과 마이의 `내 방명록`에서 `/guestbook`을 연다. 시안의 카드 표현을 기존 루트 Stack 화면에 적용해 전체 동아리의 글을 페이지 단위로 조회한다. 친구 방에서는 기존 방·통계·좋아요 아래에 현재 동아리의 방명록을 연결했다. 하나의 FlatList가 방 헤더와 방명록을 함께 스크롤하며 중첩된 세로 목록을 만들지 않는다.

내 방명록은 소속이 없거나 탈퇴한 동아리의 과거 글도 조회한다. 방문 화면은 그 방에 **현재 동아리에서** 남긴 글만 표시한다. 작성자는 현재 부원 목록에서 사용자 ID로 연결한다. 계정을 탈퇴해 `authorUserId: null`이면 `탈퇴한 사용자`, 현재 이름을 확인할 수 없으면 `작성자 정보 없음`으로 구분한다. 현재 같은 동아리의 다른 부원으로 확인한 작성자에게만 `답방 가기`를 제공한다.

## 요청과 권한

| 요청 | 용도 |
| --- | --- |
| `GET /users/me/guestbookEntries?pageSize=20` | 내 방의 모든 동아리 글·새 글 표시 |
| `GET /clubs/{clubId}/members/{memberId}/guestbookEntries?pageSize=20` | 방문 방의 해당 동아리 글 |
| `POST` 위 방문 경로 | `{ body }`만 작성 |
| `DELETE .../guestbookEntries/{entryId}` | 확인한 글 하나 삭제, 본문 없음 |
| `GET /users/me/room` | 서버의 `newGuestbookCount` |
| `PATCH /users/me/room` | `{ guestbookCheckedAt }`만 저장 |
| 내 부원 자격·현재 동아리/전체 부원 조회 | 접근·작성자 이름·답방·삭제 경로 확인 |

일반 부원도 이용할 수 있으며 관리 권한이나 역할 조회가 필요하지 않다. 본인 방에는 작성하지 않는다. 본문은 앞뒤 공백을 제거한 1~60 grapheme cluster이며, UTF-16 `maxLength`로 가족 이모지 등을 중간에 자르지 않는다. Segmenter가 없는 런타임에서는 서버의 최종 길이 검사를 따른다.

삭제는 작성자 또는 방 주인만 가능하다. 운영진 권한만으로 다른 방의 타인 글을 삭제할 수 없다. 내 전체 목록에서도 현재 동아리 자격이 있는 글에만 삭제를 제공한다. 백엔드 DELETE 경로의 `RequireClubAccess` 때문에 탈퇴한 동아리의 과거 글은 현재 계약상 읽기 전용이다. 본인 삭제 경로에도 현재 확인한 구체적인 부원 UUID를 사용한다.

모든 부원 페이지를 읽고 현재 계정·동아리·대상 ID, 글의 UUID·방 주인·동아리·작성자·본문·시각·NEW와 페이지 토큰을 검사한다. 방문 글이 다른 동아리/사용자의 것이면 표시하지 않는다. 작성자 정보 조회가 403/404인 과거 동아리는 이름/답방을 추정하지 않는다. 방명록 날짜는 일반 한국 달력 날짜로 표시한다.

## 새 글·페이지·이탈

내 방·마이의 새 글 배지는 `newGuestbookCount`를 읽기만 한다. 값이 불확실하면 숫자를 추정하지 않는다. 성공한 첫 페이지가 화면에 표시된 뒤, 목록을 열기 시작한 UTC 시각을 `guestbookCheckedAt`으로 저장한다. 목록 조회가 실패했을 때나 친구 방을 볼 때는 저장하지 않는다. 장착·배치·방 상태를 이 PATCH에 포함하지 않는다. 서버는 미래로 보낸 시각을 도착 시각으로 제한한다.

열었을 때 받은 NEW 표시는 현재 목록에 유지한다. 추가 페이지와 다음 진입은 서버의 현재 표시를 따른다. 확인 시각 저장 실패는 별도 안내하며 `방명록 다시 확인`으로 다시 조회한 뒤 저장한다. 확인 시각 변경도 서비스의 변경 큐를 사용한다. 저장 후 배지를 재조회하므로 실제 저장에 실패한 새 글 수를 0으로 만들지 않는다.

`방명록 더 보기`는 토큰을 인코딩하고 기존 글을 유지한다. 경계에서 겹친 같은 글은 중복 표시하지 않으며 내용이 다른 동일 ID·반복 토큰은 거절한다. 새 조회와 추가 페이지의 중복 실행을 막고, 다른 방·계정의 늦은 응답을 새 화면에 적용하지 않는다. 401/403/404에서는 이전 글·초안·열린 삭제 창을 내린다. 작성 중 이탈은 확인하고 변경 처리 중 Stack 제거를 막는다. 브라우저 전체 페이지 이동을 막는 기능은 아니며 초안 본문은 저장하지 않는다.

## 등록 응답 유실·삭제 확인

POST는 멱등 계약이 없으므로 전송 전에 계정·대상별 요청 기록을 저장한다. `@tamagochi/guestbook-intent/v1/{apiBaseUrl}/{userId}/{clubId}/{memberId}`의 기록에는 버전·임의 요청 식별자·pending/created 상태만 들어가고 본문은 저장하지 않는다. 저장에 실패하면 POST하지 않는다. 확정된 4xx는 이 요청 기록만 정리하며 네트워크·타임아웃·5xx·잘못된 성공 응답은 pending으로 유지한다.

성공 응답의 방 주인·동아리·작성자·본문을 검증한 뒤 created로 보존한다. 같은 본문이 목록에 있다는 이유로 미확정 요청을 성공으로 간주하지 않는다. 재실행·계정/방 전환 후에도 pending/created 기록이 있으면 자동으로 다시 쓰지 않는다. created 기록 저장만 실패한 경우 같은 서비스에서는 확인한 응답을 기억하지만 재실행 후에는 pending을 보수적으로 유지한다.

`방명록 다시 확인`은 조회만 한다. 사용자가 목록을 확인하고 `목록 확인 후 새 글 작성`의 확인창을 승인해야 기록을 해제한다. 이때 입력을 비우며 이전 POST를 재전송하지 않는다. 늦은 등록 가능성을 안내한다. 이 장치는 앱의 중복 탭·자동 재시도·재실행을 방지하며, 서버의 멱등 키가 없는 서로 다른 기기의 동시 POST를 원자적으로 막는 계약은 아니다.

삭제 전에는 모든 필요한 페이지에서 원래 글과 현재 권한을 확인한다. 이미 없으면 DELETE하지 않고, 내용이나 작성자가 바뀌면 재확인을 요구한다. 응답 유실/404/5xx는 다시 읽어 부재가 확인된 경우에만 완료로 표시하며 삭제를 자동 반복하지 않는다. 미적용·조회 실패는 읽기 전용으로 두고 수동 조회 후 명시적으로 다시 선택한다.

## Mock과 검증

`@tamagochi/mock-guestbook/v1`에 추가 글·삭제 ID·확인 시각을 저장하며 기존 부원·강퇴·탈퇴·동아리 데이터를 공유한다. 읽기만 할 때 초기 기록을 쓰지 않는다. 저장소별 변경 큐로 등록·삭제·확인 시각을 보존한다. 계정별 요청 기록과 같은 구조의 Mock 요청 기록을 별도로 사용하며 손상·실패 시 원본을 자동 삭제하지 않는다. 개인 공부·볼트·방 장착·좋아요 저장소는 수정하지 않는다.

타입·린트와 총 **321개 테스트**, API Android/iOS/Web·Mock Web 번들이 통과했다. 새 20개는 Unicode 60자·내 전체/방문 동아리 범위·작성자/삭제/답방 권한·페이지/DTO·정확한 요청 필드·재실행과 응답 유실·요청 기록 실패/손상·삭제 부재/미적용 확인·확인 시각·Mock 영속성/탈퇴/개인 기록 보존을 검증한다.

격리 Chrome의 가짜 API로 인증·새 글 배지·전체 조회·nullable 작성자·과거 동아리 읽기 전용·방 주인 삭제·조회/확인 시각 저장 실패를 확인했다. 방문 범위·작성자 삭제·초안 이탈·grapheme 입력·중복 탭·응답 유실/미적용 후 재실행·명시적 새 입력·페이지 추가·늦은 응답 폐기·접근 회수·계정 전환·만료도 확인했다.

Mock에서는 내 방/마이 진입·확인 저장 실패·삭제 취소·등록/미확정 상태 유지·저장 실패 후 수동 확인·동아리별 글/사용자별 좋아요 공유·추가 페이지·새 방문 배지·탈퇴 후 과거 글 유지/접근 차단·공부/좋아요 보존을 확인했다. 기존 친구 방·좋아요 브라우저 회귀 검증도 통과했다. 320×568·390×844·1280×844에서 가로 넘침과 카드/확인창을 확인하고 작은 화면에서 입력란 접근을 별도로 확인했다. 운영 API 네트워크를 차단해 운영 데이터를 변경하지 않았다.

실계정·Android/iOS 키보드/뒤로가기·화면 읽기·긴 목록 성능·여러 기기의 동시 등록/확인 시각 검증은 남아 있다. 최종 방 에셋과 기존 Metro 개발 SSR 문제도 별도다.

## 미리보기

`http://localhost:8082/guestbook` 또는 내 방의 `방명록`, 마이의 `내 방명록`을 연다. 친구 방은 `/friends`에서 부원을 선택하고 아래로 스크롤하면 작성란과 글이 나온다. 기본 Mock은 내 방에 새 글 3개를 제공하며, 현재 브라우저의 확인 시각·삭제·탈퇴 기록에 따라 표시가 달라진다.
